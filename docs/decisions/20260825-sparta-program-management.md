# スパルタプログラム管理（登録・自動進捗・終了判定）

## 背景

スパルタプログラム（期間を定めた暗記の取り組み・達成報酬つき）は生徒が毎日 LINE に手打ちで報告していた。
塾長の決定（2026-08-25）で実装場所を SRS とし、学習記録そのものが進捗になる形にして自己報告を廃止する。
申し込みフローは作らず、コーチングで相談 → 塾長が講師画面で登録する。
作業指示書: 統合塾運営エージェント `docs/work-orders/2026-08-25-srs-sparta-program-management.md`。

## 決定

1. **新テーブル `sparta_programs`（026）は定義だけを持ち、進捗は集計時に導出する。**
   生徒×対象ルートデッキ（配列・FKなし＝削除耐性は表示側で担保）×期間×目標カード数×習得基準×状態。
   card_states / review_logs には一切書き込まない（単語帳の定着度ビュー・庭と同じ純表示層）
2. **「習得」の判定は既存の定着度（`wordbook/mastery`）の区分を流用**。既定は「定着中以上
   （実効安定度7日以上）」。理由: 1ヶ月の期間内に途中導入したカードは「定着済み=21日」に
   物理的に届かないため。厳しめの「定着済み」も登録時に選べる（第2層判断）
3. **進捗の起点は登録時の習得済み数（baseline）を保存して差分で測る**。目標未指定なら
   「全カード − 開始時習得」が目標。対象デッキか習得基準を編集したら起点も測り直す。
   履歴スナップショットを持たない代わりの軽量な方式（登録が開始日より後だと起点がその時点になる近似は許容）
4. **日付の区切りは日本時間の午前4時**（`spartaDayKey`）。サーバー（Vercel=UTC）でも生徒の
   体感とずれない。既存の一部集計（サーバーローカル4時）とは異なるが、期間の境界が意味を持つ
   本機能では正確さを優先
5. **集計は service role client＋担当生徒チェック**（復習通知の管理 ADR 20260819 決定6と同じ理由:
   RLS 経由だと生徒の個人デッキ配下が講師から見えず集計がズレる）。生徒API（/api/sparta/mine）も
   同じ視野で集計し、対象を auth.uid() 本人の行に限定する
6. **生徒への表示はホームのカード1枚・核となる数字だけ**（対象デッキ・期限・残り日数・進捗率・
   今日実施済みか・連続日数）。習得度内訳などの細部は講師画面のみ。理由: 生徒の日々の行動に
   必要なのは「今日やるか・あとどれだけか」であり、細部はコーチングで講師が伝える（第2層判断）
7. **催促は既存の学習リマインダーに乗せる**（due-cards-summary は全ルートデッキの期限切れを
   対象にするため、スパルタ対象デッキも自動で含まれる。SRS側の変更なし）。スパルタ特有の催促
   （未着手・期限接近）は billing 側の変更が必要なため実装せず、完了報告に起案として記載
