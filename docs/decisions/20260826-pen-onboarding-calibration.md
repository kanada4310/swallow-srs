# ペン入力の初回お手本登録の義務化と、登録お手本による閉じ括弧の判別強化・記号の扱い3点の修正

## 決定

塾長の発案（2026-08-26・指示書 srs-pen-onboarding-calibration）を受けて次の3つを行う。

### 1. 記号の扱いを塾長の実書き込みに合わせる（模範分析集で裏取り済み）

quiz_generator `subjects/英語/模範分析集/`（形式仕様・第7講実データ）を正とする。
第7講の集計では、働き（下の段）に Po=80回・P=76回・▷=18回が出現し、**M は品詞・働きとも出現ゼロ**。
品詞（上の段）に前置詞の p も出現ゼロ（塾長は前置詞を下の段に P と書く）。

1. **「M」を削除**: 働きの記号一覧（`ROLE_LETTERS`）・内蔵お手本・計測のお題・お手本登録の対象から外す
2. **「P」「▷」は働きの側（下の段）**: 分類・吸着・お手本の並びとも働き側。▷ の解答値も「接」に変換せず「▷」のまま
3. **「Po」を言い換えない**: `roleLetterToAppRole`（Po→前O・▷→接・P→M の変換）を廃止し、
   画面・凡例・判定結果・記録のすべてで塾長の表記のまま扱う
4. 構文の練習の働き語彙を `ROLE_LETTER_OPTIONS`＝S・V・O・C・P・Po・▷ に統一
   （タップ方式は `SyntaxAnnotator` の新設 `roleOptions` プロパティで注入）。
   練習3問の正解表も塾長表記へ更新（修飾語には働きを書かない・前置詞は P・その目的語は Po）。
   矛盾検査（syntax-check）は「前置詞の印は品詞 p / 働き P のどちらでも可」
   「副詞には働きを書かない」「▷ を接続詞と認める」に更新
5. **読解1文画面（構文を分析する）の語彙 `ROLE_OPTIONS`（S/V/O/C/M/前O/接）は不変**。
   既存の書き込みデータ（reading_progress）・構文AI判定のプロンプト・入力検査と揃っているため、
   変更するなら別起案（データ移行を伴う）

### 2. 初回お手本登録の義務化（利用者ごとに1回だけ・2〜4分）

- **必須21種**: 括弧4種の開き・閉じ8種（**各2本**・下記3の相対比較が安定するため）＋
  品詞の英字6種＋働きの文字7種（各1本）
- **任意**: 下線・○囲み・波線＋?・ダッシュ・Ø（計測ページ下部でいつでも登録できる旨を完了画面で案内）
- 構文の練習のペン方式を初めて開くと登録の案内（`PenOnboarding`）を必ず通す。
  完了の印は localStorage に**利用者IDつき**で保存（`pen-syntax-onboarding-done-v1:<userId>`）。
  お手本本体は従来どおり端末単位の保存（既存キー不変・外部送信なし・DB変更なし）
- **途中でやめた場合（第2層・実装者判断）**: 登録済みの字はそのまま残し、次回ペン方式を
  開いたとき**続きから再開**。それまでの練習はタップ方式でできる（やめると自動でタップ方式へ切替）。
  理由: 義務化の趣旨（全種そろえて精度を出す）と、ペンの調子が悪い場面での逃げ道の両立
- **登録し直し・追加**: 練習ページ下部の控えめなリンク（全種のやり直し・スキップ可）と、
  計測ページ下部の「お手本登録」（記号を選んで個別に・括弧8種＋任意記号まで拡張＝27種）
- 既に全種登録済みの端末（塾長の計測用端末など）は案内を出さず完了扱いにする

### 3. 登録お手本による閉じ括弧（〉 ｝ ]）の判別強化

`classifyShape` が登録お手本を照合対象に受け取る。設計上の要点:

- **向きゲート**: $P 点群照合は括弧の左右の向き（開き/閉じ）の違いに弱いため、
  書かれた線の膨らみの向きと一致する括弧のお手本にだけ効かせる
- **相対比較**: 括弧の種類は「同じ向きの4種のお手本のうちどれに一番近いか」で決め、
  2位と明確な差（USER_MARGIN=0.02）があるときだけ先頭に置く。
  **4種すべて登録済みが条件**（未登録の種類があると、その記号のお手本が無いせいで
  別の種類に吸われるため）＝初回登録で括弧8種を必須にした理由
- **強い幾何特徴は尊重**: 円弧・2本線の当てはめ等が 0.9 級の確信で別の括弧を指すときは、
  お手本側により大きな差（0.08）を要求する（当てはめの得意分野を弱い証拠で覆さない）
- お手本が無いときの挙動は従来と完全に同一

機械計測（種固定・癖のある閉じ括弧の模擬 n=120）:
- 一発判別 **53.3% → 58.3%**・救済込み（候補タップ含む）**92.5% → 99.2%**・
  完全に拾えず **7.5% → 0.8%**
- 標準的な書き手が自分のお手本を登録した場合の群A: **90.6% → 91.1%**（劣化なし）

## 捨てた方式

- **お手本との近さを絶対値でスコアの下限にする方式**: $P の左右弱さのため、開き括弧の線が
  閉じ括弧のお手本に吸われ標準形が劣化（90.6→76.9%）したので廃棄。向きゲート＋相対比較に変えた
- **完了フラグをDBに持つ方式**: お手本本体が端末保存（localStorage）なので、フラグだけ
  DBにあっても端末が変われば登録し直しが必要になる。端末＋利用者IDのローカル保存で足りる
  （DB変更なし＝塾長承認も不要の範囲）

## 影響・残る弱点

- 対象は構文の練習・ペン判別の計測のみ。学習エンジン・DB・共有部品の1文画面側は不変
- お手本と完了フラグは端末単位。**端末を替えると再登録**（初回1回の約束は端末ごとに数える）。
  兄弟等で端末を共有すると、後の利用者の登録が先の利用者の字を押し出す可能性がある
  （1記号あたり最新3件保持）。実運用で問題になれば利用者別の保存キーへ分ける
- 機械計測の「癖」は合成データであり、実機の改善幅は塾長の実測（pen-lab）で確かめる
