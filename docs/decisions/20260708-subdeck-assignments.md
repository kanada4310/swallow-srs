# サブデッキの配布は「継承配布行」を明示的に作る（source_deck_id）

## 背景
配布記録（deck_assignments）は親デッキにしか作られず、サブデッキは pull API の admin client（RLSバイパス）だけで生徒に届いていた。そのため通常権限で動く API（`/api/decks/[id]/offline-data`・`/api/notes/search` 等）は RLS がサブデッキを弾き、生徒がサブデッキを個別に扱う経路が壊れていた。また deck_assignments には一意制約が無く、重複行が入り得た。

## 決定
1. **親を配布したら子孫にも配布行を明示的に作る**。`source_deck_id` 列（NULL=直接配布、非NULL=継承元デッキ）で両者を区別する（022_subdeck_assignments.sql）
2. **配布の管理は配布した階層（通常はルート）で行う**。継承行は個別解除不可（API 400＋UI で「親デッキから配布」バッジ・解除ボタン無効）。解除時は同一ターゲットの継承行も一括削除
3. 配布済み親の下に**後からサブデッキを作った場合も自動継承**（POST /api/decks でコピー・失敗は非致命）
4. **既存配布はマイグレーションでバックフィル**（重複掃除 → 部分一意インデックス → 継承行挿入 → is_distributed 同期）。再実行しても冪等
5. デッキ削除ガードは**直接配布のみ**ブロック（継承行は FK CASCADE で消える）。これをしないとバックフィル後にサブデッキが削除不能になる
6. pull API の admin client による子孫補完は**安全網として残す**
7. ついで修正: notes/search のアクセス判定が個別配布しか見ておらず**クラス配布の生徒が 403** になる既存バグをクラスメンバーシップ OR で修正

## 結果
- 生徒はサブデッキを通常権限の API でも読める（offline-data・ノート検索）
- 講師の生徒進捗・生徒統計のデッキ一覧にサブデッキ行が現れるようになる（サブデッキ単位の進捗が見える＝概ね改善）
- PostgREST の upsert は部分一意インデックスを推論できないため、伝播は select-then-insert＋一意制約違反（23505）握りつぶしで冪等化
- 配布解除しても生徒端末の IndexedDB からは消えない（既存仕様のまま）
