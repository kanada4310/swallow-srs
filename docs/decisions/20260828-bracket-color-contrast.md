# 入れ子カッコの4色を、白地で読める濃さに組み直す

## 背景

2026-08-27 に深さ別の色を「隣り合う深さが青と橙（補色に近い）」に入れ替えた
（`20260827-pen-role-band-and-colors`）。そのとき実施側から
**明るい2色は白地に対する明暗の比が 3.5:1 前後で、小さな文字に推奨される 4.5:1 に届かない**
と開示されていた。生徒に開放する前に直す。

## 決定

**4色すべてを組み直す。** 後ろ2色だけを濃くすると、2つ違いの深さ（同じ側の色）の
明るさの差がつぶれるためである。

| 深さ | 直す前 | 直した後 | 白地の比（前→後） | 明度 L*（前→後） |
|---|---|---|---|---|
| 0 濃い青 | `#00427A` | `#003368` | 10.19 → 12.55 | 27.6 → 21.5 |
| 1 濃い橙 | `#7A3800` | `#4D2801` | 8.77 → 12.97 | 31.7 → 20.4 |
| 2 明るい青 | `#3E8ED0` | `#0074DE` | **3.51 → 4.61** | 57.0 → 49.2 |
| 3 明るい橙 | `#B87200` | `#A16900` | **3.86 → 4.63** | 54.3 → 49.1 |

壊してはいけない条件3つは、いずれも満たしたまま（むしろ良くなった）。

| 条件 | 直す前 | 直した後 |
|---|---|---|
| 隣り合う深さの色相の差（補色に近い） | 141°・153°・165°・153° | 141.5°・141.5°・152.2°・152.3° |
| 2つ違いの深さの明度 L* の差（25 以上） | 29.4・**22.5** | 27.8・28.7 |
| 色覚の型ごとの、いちばん近い組の色の差 | 一般30・P型30・D型30・T型29 | 一般38.6・P型38.7・D型39.2・T型40.1 |

**直す前は「明度の差 25 以上」を深さ1↔3 が満たしていなかった**（22.5）。
コメントに書かれていた条件と実際の値がずれていたので、今回あわせて直した。

## 計算のしかた

`node scripts/bracket-colors.mjs` で出し直せる（引数に4色を渡せば任意の組で計算できる）。
- 白地に対する明暗の比: WCAG の相対的な明るさ
- 明度・色相・色の差: CIE L\*a\*b\*（D65）／色の差は CIE76
- 色覚の型の見え方: Viénot, Brettel & Mollon 1999 の二色覚シミュレーション
  （線形の RGB に当てる）。**機械計算であり、実機での見え方の実測ではない**

この道具は 2026-08-27 の ADR の数値（10.19 / 8.77 / 3.51 / 3.86、色相差 141〜165°、
最小の色の差 30/30/30/29）を再現できることを確かめてから使った。

## 見張り

`src/components/pen-syntax/bracket-colors.test.ts`（4件）が、
①4色とも白地の比 4.5:1 以上 ②隣り合う深さの色相差 141〜165° ③2つ違いの明度差 25 以上
④どの色覚の型でも、いちばん近い組の色の差が 29 以上、を毎回確かめる。
色を入れ替えるときは、ここが緑のままであることを確認する。

## 確かめたこと

開発サーバーの実ブラウザ（iPad Mini 相当・テスト講師）で「構文の練習」を開き、
模範分析集の文の正解を表示して、画面に出た4段の色を実測した:
深さ0 `rgb(0,51,104)` / 深さ1 `rgb(77,40,1)` / 深さ2 `rgb(0,116,222)` / 深さ3 `rgb(161,105,0)`。

## 影響

変更は**表示だけ**（吸着・採点・保存するデータは不変）。データベースの変更なし・費用なし。
