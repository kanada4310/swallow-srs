# 生徒ファーストのナビゲーション（下メニューは毎日使う4つ＋「もっと」に格納）

## 背景
生徒の下メニューに「ノート」「テンプレート」といったカードを**作る側の道具**が、毎日使う入口（ホーム/デッキ/統計）と同列に並んでいて、アプリ全体が難しく見えていた。経営者の方針は「生徒が日常的に見るもの（タスク・デッキ・単語帳・統計）をすぐ見えるようにし、普段使わない設定・機能は格納する」。また講師の下メニューは7項目で窮屈だった（既知の課題）。

## 決定
1. **下メニューは「毎日使うもの」だけに絞り、残りは `/more`（もっと）ページに格納する**
   - 生徒: ホーム / デッキ / 統計 / もっと（GARDEN_ENABLED 時は庭が入る）
   - 講師: ホーム / デッキ / 生徒 / 統計 / もっと
   - `/more` の中身: ノート・テンプレート・通知設定・設定・ログアウト（機能は消さない、入口を奥に移すだけ。URL 直打ちも従来どおり）
2. **ヘッダーからベル（通知設定）・歯車（設定）・ログアウトを撤去**し `/more` に集約。ヘッダーはロゴ＋ユーザー名＋同期表示のみ
3. **単語帳（定着度）は独立タブにせず、デッキ詳細の既定タブにする（生徒のみ）**
   - 理由: 単語帳はデッキごとのものなので、独立タブだと「今どのデッキ？」で迷う。「デッキ一覧 → デッキを選ぶ → 単語帳」の一直線が自然。デッキ（選ぶ）と単語帳（中を見る）は上下関係で重複ではない
   - 講師の既定はノート一覧のまま（管理作業が主）。タブの並びは単語帳を左に
4. **デッキ一覧の「新規作成」は生徒では控えめに**（ヘッダー右上→ページ最下部の点線リンク。講師は従来どおり）

## 結果
- 生徒の初見の情報量が大幅に減る。作る機能・設定はすべて `/more` 経由で到達可能（退行なし）
- `/more` は OfflineNavContext に静的登録済み＝オフラインでも開ける
- 横断ノートブラウズ（/notes）は生徒の日常導線から消えるが、経営判断として「生徒はほぼ使わない」ため許容
- 将来 BottomNav に項目を足したくなったら、まず `/more` 行きを検討する（下メニューの定員は生徒4・講師5が上限目安）
