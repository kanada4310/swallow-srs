# 構文添削AI判定の試行導入 — 実装設計

秘書ADR（統合塾運営エージェント `docs/decisions/20260821-syntax-ai-trial.md`・塾長承認済み）を受けた
swallow-srs 側の実装設計。試行の枠 = **上限月3,000円・対象生徒2〜3人・期間1ヶ月**。

## 画面と操作（現行のタップ方式の範囲で設計）

- **入口は「構文に降りる」1文画面を作業台化する。** 素振り（/reading/syntax）のタップ入力UIを
  共通部品 `SyntaxAnnotator` に切り出し、1文画面に載せる（表示だけ→書き込めるへ）。
  ペン入力は別途検証中のため待たない（指示書明記）。
- 1文画面に追加するもの:
  1. **「分からない」マーク**（波線＋?。増補 Rule 39 の自己申告。文単位のボタン）
  2. **AI判定**（許可生徒のみ表示。1往復・文順・全件の指摘リスト）
  3. **添削問答**(復習カード行きの文。チャット形式。正解を言わず辞書・文法書の引き先を指す)
  4. **復習カードへ保存**（確定した分析だけ）
- 書き込みは講の途中保存（reading_progress の JSON）に `syntax` 欄を足して保存する。
  `reconcileProgress` が新欄を落とさないよう引き継ぎ処理を追加（version は 1 のまま・後方互換）。

## 判定・確定・カード化の流れ

1. 生徒がタップで品詞・働き・まとまりを書き込む
2. 「AI判定」→ ルールブックを採点基準に、指摘を**文頭から順に全件**返す（1往復・JSON）。
   指摘の種別は共通見解の原則3に従う: 記法の運用ミス=直接示す / 判断ミス=問いの型①〜⑤で問う
3. 指摘があれば「添削問答」で1問ずつ対話 → 生徒が書き込みを直して再判定
4. **指摘ゼロの判定＝確定**。「分からない」マークが付いた文・一度でも誤りが出た文は、
   確定時に**自動で復習カード化**（裁定1）
5. カードに保存するのは**英文と確定済みの構文分析だけ**。訳文は保存しない（裁定2）

## 復習カード連携

- ノートタイプ「構文分析」（is_system・API側で自動作成）: 英文 / 分析表示 / 構文分析データ / 出典
- 生徒の**個人デッキ「構文分析カード」**に保存（初回に自動作成・オーナー=生徒本人）。
  card_states / review_logs の構造には一切触れない（新規カードは通常の新規カードとして流れる）
- 分析表示はカード作成時にHTMLへ描画して保存（テンプレートは白文=表 / 分析=裏）

## 試行の枠の機械的な担保（安全の線）

- **DB 2表**（`025_syntax_ai_trial.sql`）:
  - `syntax_ai_config`（1行）: enabled / 許可生徒 allowed_user_ids（最大3人）/ 期間 starts_at・ends_at /
    月上限 monthly_cap_yen（既定3000）/ モデル model（既定 claude-sonnet-4-6）
  - `syntax_ai_usage`: 呼び出し1回ごとの kind（judge/dialogue）・トークン数4種・概算費用（円）
- **ゲートはサーバ側で毎回判定**（`src/lib/syntax-ai/gate.ts` 純ロジック）:
  enabled → 許可一覧 → 期間内 → 当月使用額 < 上限、のすべてを満たすときだけ受け付ける。
  月の区切りは日本時間の暦月。入口の表示可否も同じゲートを status API 経由で参照する
- **講師画面 `/students/syntax-ai`**: 今月の使用額・回数・生徒別内訳・1文あたり往復数の実測を表示。
  許可生徒の選択（最大3人）・期間の開始/停止・モデル変更もここで行う

## 外部へ送る内容（絶対規程3）

- AIへ送るのは**教材の文（トークン列）と生徒の書き込み・問答の文面だけ**。
  プロンプト組み立て関数（`src/lib/syntax-ai/prompt.ts`）は氏名・ID類を引数に取らない設計で担保。
  lesson_id 等は自前DBの集計にだけ使い、プロンプトへは入れない

## 採点基準（ルールブック）の取り込み

- 正本は quiz_generator（PDF 21ページ=ルール1〜32 ＋ 増補md=Rule33〜51 ＋ 構文添削の共通見解md）。
  **テキスト化して同梱**する方式: `data/syntax-rulebook/extract_core.py`（PDF→テキスト・字間スペース除去）
  → `data/sync-syntax-rulebook.mjs`（3本を `src/lib/syntax-ai/rulebook-text.ts` に生成）。
  正本を直したら再実行して取り込み直す（読み取り専用・swallow-srs 側では編集しない）
- **プロンプトキャッシュ（1時間TTL）**: ルールブック全文を system の先頭ブロックに置き
  `cache_control: {type:'ephemeral', ttl:'1h'}`。判定と問答で同一バイト列を共有し読み直し割引を効かせる

## 費用・モデル

- モデル既定は中位 `claude-sonnet-4-6`（設定で `claude-haiku-4-5`（下位・比較用）等に変更可）
- 概算費用は公式単価（Sonnet 4.6: 入力$3/百万・出力$15/百万・キャッシュ書込1h $6/百万・読取$0.30/百万）
  ×為替（既定150円/ドル・環境変数 `SYNTAX_AI_USD_JPY` で変更可）で毎回計上
- API鍵は `SYNTAX_AI_ANTHROPIC_API_KEY` があればそれを、無ければ既存の `ANTHROPIC_API_KEY` を使う
  （鍵の発行・設定は塾長。手順は完了報告に記載）

## やらないこと（今回の範囲外）

- ペン入力（別途検証中）／口頭和訳の判定（訳はアプリに入力されない）／
  復習時の再分析採点（カードは白文→めくりで確定分析を見る形。再分析照合は将来）／
  billing 側の通知連携
