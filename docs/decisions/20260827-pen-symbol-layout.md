# 記号を付けても書く場所が動かないようにする（カッコの重ね描き・下線のベースライン・例外マークの置き場所）

## 経緯

塾長がタブレット＋ペンで「構文の練習」を使い、次の3点を挙げた。

> **下線やカッコを引いたときに、書き込もうとしていた領域自体が移動してしまう**のが地味にストレス。
> **下線はもっと文字にピッタリ出したい**（q の下の棒が下線から突き出してもよい）。
> **カッコを書くときは既存の文字幅が動かないほうが望ましい**。

模範筆順の採取のあいだ中ずっと効いてくるため、見た目の好みではなく**書き味の問題**として直す。
あわせて、第7講の検収で確定した記号の約束（決定記録 `20260827-syntax-symbol-clarifications`）を反映する。

指示書: 統合塾運営エージェント `docs/work-orders/2026-08-27-srs-pen-symbol-layout.md`

## 決定

### 1. カッコは文の流れに入れず、重ねて描く

**採用**: カッコ（開き・閉じ・**閉じ待ちの書きかけ**）を単語の並びから外し、
採寸した単語の箱から求めた座標で別の層に重ねて描く（`snap.ts` の `bracketMark`）。
下線がすでに同じ仕組みで安定して動いているため、**作り方を増やさずに済む**。

置き場所は**単語と単語のすき間の中央**。すき間は左右の語の余白ぶん空いており、
実測（開発環境・iPad Mini 相当の幅）で **12〜19画素**あるので文字とは重ならない。
入れ子は `BRACKET_SLOT_W`（6画素）ずつ左右に振り分け、カッコの文字は 24→20画素に詰めた。

**見送った案**:
- すき間を先に空けておく: 動かないが**常にすき間が空いて緩む**（塾長の懸念どおり）
- 既存のすき間にそのまま収める: 語間は4画素しかなく、開きカッコ（24画素相当）が入らない

### 2. 開始カッコの真下の働きは、横位置と縦位置の両方で判定する

先行作業（`20260827-pen-write-as-on-paper`）で入れた「単語のすき間に書いたか」の判定は
**横位置しか見ていなかった**。文が折り返していると、上の行のカッコに吸われる経路が残る
（審査の指摘）。**その行の働きの段に書かれたこと**（単語の高さの1.5倍まで）を条件に足した。

### 3. 下線は文字のベースラインのすぐ下に引く

`TokenBox` に `baseline` を足し、語の末尾に置いた**中身の無い inline-block の下端**を測る
（外枠の下端は下枠線・下余白を含むためベースラインではない）。
**q・y・g・p が下線を突き抜けてよい**（塾長の明示の希望）。突き抜けを避ける処理は入れない。
実測で下線は語の外枠下端より **13画素上**（ベースライン）に上がった。
この縦位置は**表示にしか使わない**（吸着・採点には無関係）。

### 4. ○で囲んだ例外マークは働きの欄に置く

単語の右肩ではなく**働きの欄**へ移す（塾長の指示）。1マス1値のままで衝突しないのは、
2026-08-26 の裁定による:

- **仮・真は働きと組んだ1つの値**（「仮S」「真S」＝実際の書き方）
- **強・同は単独で1マスを占める**（他の働きを持たない）

組み立ては純関数 `roleCellParts`。並びは**台帳（`EXCEPTION_KANJI`）の順**で決めるので、
「仮→S」でも「S→仮」でも同じ結果になる（自動テストで固定）。

### 5. 例外マークは○囲みの1字にする

`EXCEPTION_KANJI` を `['仮','真','強調','同格']` → **`['仮','真','強','同']`** に直した
（決定記録 `20260827-syntax-symbol-clarifications` の1）。凡例・お手本の一覧・
判別の候補・構文の練習の説明もあわせて直した。
構文の練習の働きの選択肢に残っていた「同格」も**「同」**にそろえた（実装者判断・下記）。

## 実装者判断（第2層）

- **2文字で登録済みの古いお手本（強調・同格）は引き継がず、放置する。**
  2文字を書いた筆跡は1字の照合には使えないため、引き継ぐと**誤ったお手本**になる。
  どちらも任意登録なので、放置しても初回登録の案内は出ない（迷ったら登録し直してもらう側に倒す。
  お手本の持ち主の扱い `20260827-pen-write-as-on-paper` と同じ考え方）
- **働きの選択肢の「同格」を「同」に変える。** ○囲みの「同」と別表記が並ぶと
  同じ概念が2通りになるため。構文の練習の解答はサーバーに保存していないので移行は不要
  （読解1文画面の `ROLE_OPTIONS` は既存データ・構文AIと揃えるため**不変**）
- **カッコの重ね描きと下線・例外マークの変更は同じファイルに入り組むため、1つのコミットにまとめた**
  （ファイル単位で分けると、どのコミットにも両方の変更が混じって かえって読みにくくなる）

## 確認したこと（開発環境・実機ではない）

- 開発サーバーの実ブラウザ（Playwright・iPad Mini 相当・テスト生徒アカウント）で、
  例文①②③の「正解を表示」を出して座標を実測:
  - カッコは単語のすき間の中央に置かれ、**文字と重ならない**（例文②「standing」の前の
    すき間は12.1画素、そこに置いた 〈 の幅は13.9画素で、左右の語の余白の中に収まる）
  - **一番せまいすき間に入れ子で2つ**並べた場合だけ、内側のカッコが次の語の1文字目に
    **1画素ほどかかる**（読めなくはない。これ以上詰めると記号が見えにくくなるため据え置き）
  - 下線は語の外枠下端（80）ではなく**ベースライン（67）の1画素下**に引かれた
  - 働きの欄に「S ○強」と出ることを実操作で確認（○囲みの1字）
- 自動テスト: 「カッコを足しても単語の位置は動かない」「折り返しのある文で別の行の
  カッコに吸われない」は、**直す前のコードでは落ちること**を確認済み
