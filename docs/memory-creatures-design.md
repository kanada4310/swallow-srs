# 記憶のいきもの育成（Memory Creatures）設計メモ

つばめSRS のゲーミフィケーション中核設計。Phase 10 の実装はこの文書を一次仕様とする。
（2026-06-14 ディスカッションで合意。実装はコード未着手＝計画段階）

## コンセプト

**1ノート＝1匹の生き物。** 単語帳を「無数の小さな生き物を飼う庭」として捉える。
全体の進捗で1キャラを育てるのではなく、**1枚1枚のカードがそれぞれ独立した生命**であり、
互いに関係しつつも個々に大切。デッキ＝その生き物たちの巣（ハビタット）。

### なぜSRSと噛み合うのか

**新しい学習データを一切必要としない。** すべて既存の FSRS `card_states` から導出できる。
育成ゲームは学習エンジンの上に被せる**コスメティック層**であり、スケジューラには手を入れない。

| 生き物の状態 | 元データ（既存の `card_states`） |
|---|---|
| 成長段階（卵→芽→成長期→成体→完全体） | `stability`（記憶の持続日数）をそのまま成長軸に |
| 空腹・しおれ（要世話） | `due` 超過の度合い |
| 病気・傷つきやすさ | `lapses`（忘却回数） |
| 種の個性（気難しさ等の演出） | `difficulty`（FSRS難易度） |
| 種類（植物/鉱石/動物…） | `note_type` または タグ |

生死・成長は生徒ごとの `card_states` から導出されるため、**生き物の状態は本質的に生徒ごと**
（配布デッキはノートを共有するが、card_states は個人別）。

## 成長段階マッピング（stability 基準・暫定）

| 段階 | 条件（暫定） | 見た目 |
|---|---|---|
| 卵 | state = new | たまご（未孵化） |
| 孵化／芽生え | state = learning | ひな／芽 |
| 成長期 | stability < 21日 | 若い芽〜苗 |
| 成体 | 21日 ≤ stability < 60日 | 成長した姿 |
| 完全体 | stability ≥ 60日 | 完成形・誇りの対象 |

- しきい値は実データを見て調整する（FSRS の retention 設定にも依存）。
- `lapses` が多い個体は、同じ stability でも「弱っている／傷がある」見た目に寄せる。

## 世話＝復習（状態オーバーレイ）

`due` 超過に応じて、成長段階の上に「世話が必要」の状態を重ねる：

| 状態 | 条件（暫定） | 演出 |
|---|---|---|
| 健やか | due 未到来 | 通常 |
| おなかすいた | due 超過（軽度） | 空腹アイコン |
| しおれ気味 | due を `interval` の数倍超過 | しおれた見た目 |
| 危篤 | さらに長期放置 | 弱り切った見た目 |
| 死（墓石） | 致命的に長期放置 | 墓石に変化 |

学習画面では復習を「エサやり／水やり」として演出し、正答で成長アニメを出す。

## 死＆復活メカニズム（重要・SRSとの両立）

学習科学を壊さないため、以下を厳守する：

- **「死」は見た目の層に限定する。** スケジューラや card_states を破壊しない。
- **「ゼロから育て直し」は FSRS が自然に実現する。** 長期放置カードを久々に復習すると
  ほぼ Again になり、FSRS が `stability` を大きく下げる → 株が種／芽に戻り芽吹き直し。
  「サボった結果わからなくなって、また一から」が科学的に正しいまま成立する。
- **死（枯れ）は必ず復活可能にする（安全弁）。** 枯れた株に水やり（=復習）で芽吹き直す。
  永久ロストにはしない。罰ではなく「もう一度育てよう」の温度感。
  「枯れだらけ」で心折れないための UX 配慮（しおれ→枯れ→芽吹き直しの穏やかな循環）。
- **検討された代替（採用しない）**: 死亡時に該当カードを強制的に新規リセットする Option B。
  SRS の蓄積を捨てるトレードオフがあるため、まずは上記の自然リセット方式を採る。
  後日「もっと強い喪失感」が必要になった場合の選択肢として記録のみ。

## 個別の見た目（果樹・花きの選択＝インプリント）

「全部別の絵」を手続き生成で量産するのではなく、**学習者が育てる種類を選ぶ**方式に変更。
果樹／花きの**有限の種類セット**から選べれば十分な個別性が出るうえ、イラスト制作が圧倒的に簡単。

1. **品種カタログ（有限・手描きで用意できる規模）**
   - 果樹: りんご／みかん／さくらんぼ／ぶどう／レモン／いちじく…
   - 花き: ひまわり／チューリップ／ばら／コスモス／あさがお…
   - 各品種に「種 → 芽 → 苗 → 成株 → 開花/結実」の成長スプライトを用意。
   - 必要なら品種内で色違い等の軽い種シード変化を足してもよい（任意・後回し可）。

2. **初回インプリント（生徒が品種を選ぶ）= キーワード法／視覚化記憶術**
   - そのノートに初めて触れた時、生徒がカタログから「この単語はこの果物/花」と選ぶ。
   - 単語に自分のイメージを結びつけると定着する（記憶術として機能）のが本質的な価値。
   - **生徒ごとの個別データ。** 配布デッキ共有でも生徒Aと生徒Bの同じノートは別の株。
   - （任意）AIに見出し語から品種を提案させる初期値も可（apple→りんご 等）。

### 必要なデータモデル追加（唯一の新規）

生徒×ノートのコスメ用テーブル（小規模）を1つ追加する：

```
user_creature_state (
  user_id    UUID,
  note_id    UUID,
  imprint    JSONB,   -- 選んだ品種(果樹/花き)・色違い等のバリアント
  nickname   TEXT,    -- 任意のニックネーム
  ...
  PRIMARY KEY (user_id, note_id)
)
```

- card_states（生死・成長の導出元）はそのまま。これは「見た目の刻印」だけを持つ。
- オフライン（Dexie）対応必須。

## ランキング・集計レイヤー（公平性配慮）

- ストリーク、デイリーミッション（今日◯匹の世話）。
- クラスランキングは**絶対量ではなく成長率**で競う（学習が遅い子に配慮）。
- プライバシー: オプトアウト可能に。
- バッジ: 「初めての完全体」「100匹の庭」「お墓参りで復活」等。

## アートディレクション（決定: 2026-06-14・植物に確定）

**植物（果樹・花き）系に確定。** 動物/モンスター系は一度検討したが、植物に戻す。理由:
①水やり＝復習・枯れる＝死 のメタファーが直感的、②育てる果物/花を**選べる**ようにすれば
手続き生成に頼らず十分な個別性が出る、③有限の品種セットなので**イラスト制作が簡単**。

**タッチ（重要）**: 自然で素朴・落ち着いた手描き風イラスト（最初の植物アイコンの質感）。
単線（細め）＋ミュートなアースカラー（くすんだ緑／クレイ／オーカー／ほんのり色づく花や実）。
**高校生も使うため幼すぎる表現は避ける**——ビビッドなキャンディカラーや過剰な擬人化はしない。
ネイチャージャーナル／植物図鑑のような、ほっとする質感を狙う。

- **成長段階の見た目**: 種 → 芽 → 苗 → 成株 → 開花/結実（完全体）。`stability` 段階に対応。
  伸びる・葉が増える・最後に花/実がつく、という分かりやすい上昇。
- **弱り/枯れ**: 同じ株が「しおれる（葉が垂れ色あせ）→ 枯れる（茶色・落葉）」。
  枯れ株は共通の表現（種類問わず茶色く枯れる）。水やりで芽吹き直し。
- **個別性は品種選択で担保**: りんご/みかん/さくらんぼ/ぶどう…・ひまわり/チューリップ/ばら…。
  品種ごとに5段階スプライトを用意（有限・手描き可能な規模）。

## ハビタットビュー（箱庭／森／野原）★体験の中心

「今育てている株」を一望できる**箱庭型の俯瞰ビュー**。森や野原のような連続した風景に、
各ノート＝1株が点在し、成長段階・水やり要否がひと目で分かる。

- デッキ＝ひとつの野原/果樹園/花畑。株が育つほど風景が豊かになる（達成感）。
- 「今日 水やりが必要 N株」を強調 → ワンタップで学習（＝水やり）へ。
- しおれ/枯れの株が見た目で分かり、世話したくなる導線に。
- オフライン（Dexie の card_states）から株の状態を導出して描画。
