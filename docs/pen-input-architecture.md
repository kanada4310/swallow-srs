# ペン入力の基盤・設計の1枚（2026-08-26 作成 / 2026-08-27 まとめ判定・候補の扱い・お手本の持ち主・記号の重ね描きを追記 / 2026-08-31 ○囲みの選択式化・候補の自動確定・働きの付け替え・行またぎ下線・縦ずらしを追記 / 2026-09-01 実書き蓄積・しきい値・吸着の中央境界を追記）

構文分析のペン入力を改修するセッションが**最初に読む1枚**。
層と責務・座標の約束・機種差の吸収点・記号の台帳の在りかをここにまとめる。
（経緯の詳細は ADR `20260826-pen-foundation-hardening` と各ハンドオフ）

## 層と責務（下から上へ）

| 層 | ファイル | 責務 |

| 採寸 | `useTokenBoxes.ts` | 単語の箱の採寸を**毎描画後に自動でやり直す** |
| 診断 | `input-log.ts` / `replay.ts` / `replays/` | 入力の記録と、その**再生テスト** |
| 部品 | `PenSyntaxAnnotator.tsx` / `EnrollCanvas.tsx` / `PenOnboarding.tsx` | 画面。判別・反映は上の層を呼ぶだけ |

**書き足すときの原則**: 入力イベント・座標変換・画面固定に触る変更は
useStrokeCanvas / zone-guard / useTokenBoxes の3か所**だけ**で行う。
まとめ判定・待ち時間・確定は `useStrokeGrouping` と `grouping.ts` **だけ**で行う。
画面部品に直接ポインタ処理やタイマーを書かない（過去に4か所へ重複して不具合の温床になった）。

## 画のまとめ（いつ「1つの記号」として確定するか・2026-08-27）

判定は `grouping.ts`（純関数）、配線は `useStrokeGrouping`。詳細は
ADR `20260827-pen-commit-latency`。

- **ペンが触れた瞬間**に、直前のまとまりと行・段・単語がちがうと分かれば
  **待たずに確定**する（紙と同じテンポ。1点しか分からないので確信のある根拠だけで切る）
- 場所の比較相手は**直前の1画**（まとまり全体の外接箱ではない。広がった箱が
  以降の画を吸い込む経路を断つ）
- 切る根拠の順: 間があいた → 行 → 段 → 横長の線（下線・波線は1画で完結）→
  単語をまたいだ → 単語がちがう → 記号として大きすぎる → 離れている
- **同じ単語の同じ段で書き続けている間は待つ**（○で囲んだ漢字・2画の S/V・
  括弧の書き直しを切らない）。待ち時間 0.75 秒は据え置き
- 確定のたびに「入力の記録」へ待ち時間を残す。計測ページに実測欄がある

## 実書き蓄積と判別の確定（2026-09-01・検討会確定内容 v1）

詳細は ADR `20260901-pen-stroke-accumulation`（方式の合意は
統合塾運営エージェント `docs/proposals/2026-08-31-文字認識検討会記録.md`）。

- **照合対象は三段重ね**: 塾の共通お手本集（DB・名前を付けない形）＋本人の蓄積（DB・
  利用者ごと）＋端末内のお手本（localStorage・従来）。合成は `mergeStores`、
  読み書きは `usePenTemplates`（練習を開くときに読み、オフライン・DB未適用時は
  端末内だけで従来どおり動く）。**判定は今までどおり端末内・書いた瞬間**
- **関所**: たまるのは本人が確定し訂正しなかった線だけ。PenSyntaxAnnotator が反映済みの
  線を鍵つきでため、取り消し・削除・値の変更で外し、**採点時に**まとめて送る。
  候補から選び直した線は source=chip（正解確定済みの最良のお手本）
- **保存する線の形**: 形を保つ間引き（Douglas-Peucker 方式・48点以下）＋0.1px丸め・時刻なし。
  等間隔の打ち直しで間引くと点群照合に位相ずれの下駄（0.2〜0.3）が付くので使わない
- **確定の規則**（`tuning.ts` が正本）: 最有力があり・2位との差が十分・**確信が下限以上**
  （形0.7・文字0.55）のときだけ自動確定。下限未満・本人のお手本と意見が割れたときは
  候補選びへ（取り違え最優先）。**続け書き時の自動確定にも同じ下限**を適用し、
  下限未満は破棄せず保留列（heldChips）に残して後から選べる
- **括弧の吸着は単語の中央が境界**（2026-09-01 項目4）: 同じすき間に重ねた括弧・
  狭くて食い込んだ線も同じ単語に付く（「一番近い端」だと1語ぶん前後した）

## お手本の持ち主（2026-08-27）

詳細は ADR `20260827-pen-write-as-on-paper`。

- お手本（`user-templates.ts`）の保存の鍵は**利用者ごと**。
  利用者の付いていない古い保存は読み込まない（他人の字を引き継がない）
- 初回登録が要るかどうかは「完了の印」ではなく
  **本人のお手本が必須の種類ぶんそろっているか**（`needsEnrollment`）で決める。
  印だけを見ると、印が本人・中身が他人という食い違いを見逃す
- 登録の状況は構文の練習の下部に「お手本の登録: N / 20 種」として出す

## 迷ったときの候補（チップ）の扱い（2026-08-27 / 2026-08-31 に後始末を変更）

詳細は ADR `20260827-pen-chip-interrupt` と `20260831-pen-ux-refinements`。
**書き込み部品と計測ページの両方に同じ扱いを入れる。**

- 候補が出ていても**書き込みの受付は止めない**（`active` に候補の有無を混ぜない）。
  止めると、続けて書いたときに次の1画目が黙って消える＝「ペンが反応しない」と同じ体験になる
- **書き始めたら候補は閉じて取り置き、その1画目からそのまま描く**。後始末は線の行方で分ける
  （2026-08-31）: 続けて書いた→**最有力候補で自動確定**（従来は破棄され判定が失われた。
  誤りは判定欄のタッチで直せる）／枠の外の軽いタップ→閉じるだけ（✕と同じ破棄）。
  自動確定は「入力の記録」に残し、計測ページでは救済（候補）として数える（お題は据え置き）
- 「候補を押す操作」と「書き始め」は**当たり判定で分ける**（候補の枠 `z-20` は
  キャンバス `z-10` より上。押した接触はキャンバスに届かない）。時間・距離のしきい値は増やさない
- 候補の枠の外の**軽いタップは閉じるだけ**（品詞・働きの一覧までは開かない）
- 計測ページでは、書いて閉じた線は**計測に数えない**（お題は据え置き）
- 閉じたことは「入力の記録」に1行残す（端末内のみ）
- **置き場所は「いま書いた場所の反対側」**（`chip-place.ts` の純関数＋`useChipPlacement`）。
  品詞の段に書いたら行の下・働きの段に書いたら行の上。左右のはみ出しは抑え、
  上下どちらも枠に収まらないときは**枠の外（下）へはみ出させる**
  （枠の中へ無理に収めると必ず書いた場所か本文を隠すため）

## ゾーン方式（画面ガード・2026-08-26 塾長裁定）

画面は3区域。目印は DOM 属性（`zone-guard.ts` の定数）。

- **書き込みエリア**（`data-pen-write-zone`）: ペン専用。指・手のひらは無効
- **ペン用の操作部品**（`data-pen-ui`・候補チップ/一覧/お手本登録の枠）: ペンも指も使える
- **それ以外**: ペンは無効（書く道具に徹する・ボタンは指で押す）。**指は常時有効**（時間窓の待ちなし）

手のひら対策は2段:
1. 線を描いている最中は `freezeScreenDuringStroke` が画面全体の移動を止める
2. **ペン接触中に始まった指はどの区域でも止め、離れるまで止め続ける**（載せたまま書ける）

ペン由来の互換タッチ（touchType=stylus / 直近ペンと時間・位置が近い）は常に通す
（止めるとペンのタップがクリックにならない）。

## 記号の重ね描き（2026-08-27）

詳細は ADR `20260827-pen-symbol-layout`。**記号を足しても単語の位置は動かさない。**

- **括弧は文の流れに入れない**。単語の並びとは別の層に、採寸した箱から求めた座標で
  重ねて描く（`snap.ts` の `bracketMark`）。流れに差し込むと、書いた瞬間に後ろの単語が
  右へ押されて「書き込もうとしていた場所が動く」（塾長の実機の指摘）
- 置き場所は**単語と単語のすき間の中央**。すき間は左右の語の余白ぶん（実測で12〜19画素）
  空いているので文字とは重ならない。入れ子は `BRACKET_SLOT_W` ずつ左右に加えて
  **`BRACKET_SLOT_H` ずつ縦にもずらして斜めに離す**（2026-08-31。横だけでは
  せまいすき間で字が重なって読めなかった）。縦の並びは開き・閉じとも外側のまとまりほど上
  ＝同じまとまりの開きと閉じが同じ高さにそろう
- **下線は文字のベースラインのすぐ下**（`TokenBox.baseline`＝語の末尾に置いた
  中身の無い inline-block の下端を採寸）。q・y・g・p が下線を突き抜けてよい
  （塾長の明示の希望。突き抜けを避ける処理は入れない）
- **採点の指摘も文の流れに入れない**（`snap.ts` の `noteMark`・2026-08-27 第11便）。
  その単語の働きの欄のすぐ下に重ねて描く。文面は1マスに収まるよう「品詞 n」の形に短くする。
  置き場所（2行ぶん24画素）は採点していないときも枠の下余白として常に確保する
- **同じ行の働きは同じ高さの帯にそろえる**。マスの高さは `snap.ts` の `ROLE_ROW_H`（24画素）
  に1本化し、カッコの真下の働きも同じ上端・同じ高さ・同じ文字の大きさで中央そろえに置く
- **入れ子の深さの色は、隣り合う深さが青と橙（ほぼ補色）**になる並び
  （深さ0=濃い青 `#003368` / 1=濃い橙 `#4D2801` / 2=明るい青 `#0074DE` / 3=明るい橙 `#A16900`。
  2026-08-28 に、明るい2色が白地で薄かったため4色とも組み直した）。
  同じ側の色は濃さで分ける。赤と緑の見分けに頼らないので色覚の型によらず差が残る。
  白地に対する明暗の比は4色とも 4.5:1 以上。数値は `node scripts/bracket-colors.mjs` で出し直せ、
  条件は `src/components/pen-syntax/bracket-colors.test.ts` が見張る
  （ADR `20260827-pen-role-band-and-colors` / `20260828-bracket-color-contrast`）
- これらの縦横位置は**表示にしか使わない**（吸着・採点には無関係）。
  重ね描きは枠線の内側が基準なので、流れの中の要素より常に1画素だけ下・右にある
  （下線・カッコ・注記で共通のため見た目には出ない）

## 座標の約束

- ペンの座標は**毎イベントで枠の位置を測り直して**枠相対に直す（スクロール追従）。
  ピンチズーム中（visualViewport が変形中）は**ブラウザ計算の要素相対座標**に切り替える
  （`local-point.ts`。座標系の食い違いによる線ずれ対策）
- 単語の箱は `useTokenBoxes` が**条件の列挙なしで**毎描画後に測り直す
  （React の再描画すべて＋ResizeObserver＋フォント読み込み）。
  「◯◯が変わったら測り直す」という個別条件を書き足さないこと（下線ずれの再発経路）

## 機種差の吸収点

- 接触の受理（ペン/指/マウス・接触サイズ）: `palm.ts` の `evaluatePointer`
- ペン由来の互換タッチの見分け: `palm.ts` の `classifyTouchContact`
- ポインタ捕捉の失敗・offsetX 非対応・visualViewport 非対応: `useStrokeCanvas` / `local-point.ts` が握る
- ペンの無い端末の逃げ道: 練習ページの「指・マウスでも書く」（policy='any'。ガードごと外れる）

## 記号の台帳（確定版・2026-08-26 / 2026-08-31 に例外の印を選択式化）

正本は `ledger.ts`。使う記号は
**括弧4種＋下線＋波線（熟語）／品詞 n・v・a・ad・aux／働き S・V・O・C・P・Po・▷・＋・同／例外の印1字（仮・真・強・同）**。
例外の印は **2026-08-31 から手書きの○囲みでは書かず、マスをタッチして付ける**
（仮・真＝判定済みの S / O のマスから・強＝働きのマスの選択肢から・同＝働きの一覧の「同」。
`classifyExceptionMark` は残るが `recognizeGroup` から呼ばない）。
データの入れ物は入力経路によらず1つ（ADR `20260831-pen-ux-refinements`）:
**仮・真・強は `extras`（採点対象外。正解表に定義が無く、強は働きの値と同じ単語に共存する）／
同は `answer.role`（働きの値・採点される。正解表の「同格」と `roleBase` で同値）**。
表示は単語の右肩ではなく**働きの欄**（`roleCellParts`）。仮・真は働きと組んだ1つの値（仮S）、
強は単独の印として並ぶので、1マス1値のまま衝突しない。
深さ（S′ など）は書かず括弧から自動判定（色＋控えめなダッシュ印。照合では
`dash-notation.ts` がダッシュ表記へ相互変換＝採点同値）。
[ ] と { } は**開始カッコの真下**にまとまり全体の働きを書ける（`StudentSpan.role`）。
**閉じる前（閉じ待ち）でも書ける**＝先に書いた働きは閉じ括弧の到着時に引き継ぐ。
まとまり全体の働きかどうかは、吸着した単語ではなく
**単語のすき間（＝カッコの列）に書いたか**で判定する（カッコの列は12画素ほどしかなく、
吸着では左どなりの単語に取られる。2026-08-27 実ブラウザで確認）。
判定は**横位置と縦位置の両方**を見る（縦を見ないと、折り返しのある文で
別の行のカッコに吸われる。2026-08-27 の審査の指摘）。
台帳外の形（?・ダッシュ・Ø・○囲み・M）は検出しても反映せず、書き方を案内する。

## 働きの付け先と行またぎ下線（2026-08-31）

詳細は ADR `20260831-pen-ux-refinements`。どちらも `apply.ts`（純ロジック）に閉じる。

- **働きの記号は、下線の塊のどの単語の下に書いても塊の最後の単語に付く**
  （`roleTargetIndex`。末尾の句読点は除く。タッチでマスを直接選んだときは付け替えない）
- **行をまたぐ下線は3条件がそろったときだけ連結**する:
  前の行の末尾まで達している／その下線に働きが未記入／次の行の行頭から始まっている。
  許容誤差は**語単位**（句読点のみ無視。画素単位のしきい値は持たない）。
  判定に全行分の単語箱が要るため、`applySymbol` は追加情報
  （`tokens`＝句読点の見分け・`allBoxes`＝全行の単語箱）を任意引数で受け取る

## 実機不具合が出たら（記録→再生テスト）

1. 計測ページ（または構文の練習の「入力の記録」）で症状を再現 →「**再生用をコピー**」
2. 貼り付けた JSON を `src/lib/pen-syntax/replays/` に保存
3. `replay.test.ts` に期待する挙動を1件足す
   （`replayGuard` / `replayLocalPoints` / `strokeShifts` / `replayGrouping`）

これまでの実機不具合4件（ペン無反応・線ずれ・指スクロール不能・
続けて書いた記号が1つにまとまる）は収録済み。
「カッコを書くと書く場所が動く」（2026-08-27）は**位置の計算の不具合**なので、
記録の再生ではなく座標のテスト（`bracketMark` と部品の位置比較）で押さえている。
