# ペン入力の基盤・設計の1枚（2026-08-26）

構文分析のペン入力を改修するセッションが**最初に読む1枚**。
層と責務・座標の約束・機種差の吸収点・記号の台帳の在りかをここにまとめる。
（経緯の詳細は ADR `20260826-pen-foundation-hardening` と各ハンドオフ）

## 層と責務（下から上へ）

| 層 | ファイル | 責務 |
|---|---|---|
| 幾何・照合 | `src/lib/pen-syntax/geometry.ts` / `pdollar.ts` | 線の特徴量・$P 点群照合（純関数） |
| 記号の台帳 | `src/lib/pen-syntax/ledger.ts` | **使う記号の正本**。表示名・登録一覧・台帳外の形の案内文 |
| 判別 | `shapes.ts`（形）/ `letters.ts`（文字）/ `recognize.ts`（入口・○囲み漢字） | 画のまとまり→記号候補。お手本（`templates.ts` 内蔵＋`user-templates.ts` 本人の字） |
| 吸着 | `snap.ts` | 記号→単語の位置（行分け・開き/閉じ・範囲） |
| 反映 | `apply.ts` | 記号→解答データ（span・品詞・働き・extras）。台帳外は反映せず案内 |
| 深さ | `dash-notation.ts` | 括弧からの深さの自動判定・ダッシュ表記との相互変換（採点同値） |
| 入力 | `src/components/pen-syntax/useStrokeCanvas.ts` | **入力イベントの一本化**: 受理判定→捕捉→画面固定→座標変換→線の組み立て→記録 |
| 画面ガード | `zone-guard.ts`（判定）＋ `usePenZoneGuard.ts`（配線） | ゾーン方式（下記） |
| 採寸 | `useTokenBoxes.ts` | 単語の箱の採寸を**毎描画後に自動でやり直す** |
| 診断 | `input-log.ts` / `replay.ts` / `replays/` | 入力の記録と、その**再生テスト** |
| 部品 | `PenSyntaxAnnotator.tsx` / `EnrollCanvas.tsx` / `PenOnboarding.tsx` | 画面。判別・反映は上の層を呼ぶだけ |

**書き足すときの原則**: 入力イベント・座標変換・画面固定に触る変更は
useStrokeCanvas / zone-guard / useTokenBoxes の3か所**だけ**で行う。
画面部品に直接ポインタ処理を書かない（過去に4か所へ重複して不具合の温床になった）。

## ゾーン方式（画面ガード・2026-08-26 塾長裁定）

画面は3区域。目印は DOM 属性（`zone-guard.ts` の定数）。

- **書き込みエリア**（`data-pen-write-zone`）: ペン専用。指・手のひらは無効
- **ペン用の操作部品**（`data-pen-ui`・候補チップ/一覧/お手本登録の枠）: ペンも指も使える
- **それ以外**: ペンは無効（書く道具に徹する・ボタンは指で押す）。**指は常時有効**（時間窓の待ちなし）

手のひら対策は2段:
1. 線を描いている最中は `freezeScreenDuringStroke` が画面全体の移動を止める
2. **ペン接触中に始まった指はどの区域でも止め、離れるまで止め続ける**（載せたまま書ける）

ペン由来の互換タッチ（touchType=stylus / 直近ペンと時間・位置が近い）は常に通す
（止めるとペンのタップがクリックにならない）。

## 座標の約束

- ペンの座標は**毎イベントで枠の位置を測り直して**枠相対に直す（スクロール追従）。
  ピンチズーム中（visualViewport が変形中）は**ブラウザ計算の要素相対座標**に切り替える
  （`local-point.ts`。座標系の食い違いによる線ずれ対策）
- 単語の箱は `useTokenBoxes` が**条件の列挙なしで**毎描画後に測り直す
  （React の再描画すべて＋ResizeObserver＋フォント読み込み）。
  「◯◯が変わったら測り直す」という個別条件を書き足さないこと（下線ずれの再発経路）

## 機種差の吸収点

- 接触の受理（ペン/指/マウス・接触サイズ）: `palm.ts` の `evaluatePointer`
- ペン由来の互換タッチの見分け: `palm.ts` の `classifyTouchContact`
- ポインタ捕捉の失敗・offsetX 非対応・visualViewport 非対応: `useStrokeCanvas` / `local-point.ts` が握る
- ペンの無い端末の逃げ道: 練習ページの「指・マウスでも書く」（policy='any'。ガードごと外れる）

## 記号の台帳（確定版・2026-08-26）

正本は `ledger.ts`。使う記号は
**括弧4種＋下線＋波線（熟語）／品詞 n・v・a・ad・aux／働き S・V・O・C・P・Po・▷・＋・同格／○で囲んだ漢字（仮・真・強調・同格）**。
深さ（S′ など）は書かず括弧から自動判定（色＋控えめなダッシュ印。照合では
`dash-notation.ts` がダッシュ表記へ相互変換＝採点同値）。
[ ] と { } は**開始カッコの真下**にまとまり全体の働きを書ける（`StudentSpan.role`）。
台帳外の形（?・ダッシュ・Ø・単語囲みの○・M）は検出しても反映せず、書き方を案内する。

## 実機不具合が出たら（記録→再生テスト）

1. 計測ページ（または構文の練習の「入力の記録」）で症状を再現 →「**再生用をコピー**」
2. 貼り付けた JSON を `src/lib/pen-syntax/replays/` に保存
3. `replay.test.ts` に期待する挙動を1件足す（`replayGuard` / `replayLocalPoints` / `strokeShifts`）

これまでの実機不具合3件（ペン無反応・線ずれ・指スクロール不能）は収録済み。
