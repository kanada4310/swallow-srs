# 講師用の正解表を、講師だけが読める入口の向こうへ移す

## 背景

「構文の練習」には、模範分析集 第7講から取り込んだ**講師用の35問**（共有事項 C24）がある。
記号の一部が落ちており許容解も無いため、**生徒には出せない**問題である。

2026-08-27 の作りでは、これを講師にだけ見せる担保が**画面側の判定1か所だけ**だった。

- 判定は `src/app/(student)/reading/syntax/page.tsx` の
  `profile?.role === 'teacher' || profile?.role === 'admin'`（画面が持っている記録を見ているだけ）
- 正解表そのもの（`src/lib/reading/syntax-instructor-data.ts`・約174キロバイト）は
  **画面のコードに同梱**されていた。「講師のときだけ後から読み込む」形にしても、
  そのファイルは配信物の一部なので**誰でも取りに行けた**

実害の大きさは限定的で、出るのは正解表だけ（教材の本文は含まない設計）。
それでも**生徒が使い始めてからでは直しにくい**ため、開放の前に塞ぐ。

## 決定

**置き場そのものを変え、役割を確かめる入口を1つだけ作る。**
2026-08-27 の教材本文（`20260827-reading-data-behind-login`）と同じ形だが、
**入口が見るものが1段深い**。

1. 正解表を `private/syntax-problems/英語長文最前線_第7講.json` へ移す（配信されない場所）。
   取り込み（`data/sync-syntax-problems.mjs`）の出力先も同じ場所に変えた
2. 入口 `GET /api/reading/syntax-problems` を新設し、`requireTeacher` で
   **`profiles` の役割をサーバー側で確かめてから**返す。
   画面から送られてきた役割は信じない（生徒は 403・未ログインは 401）
3. 画面は入口から取りに行く形にした。画面側の判定は「見せ方」だけの役割になる
4. 端末や中継に残さない指定（`cache-control: private, no-store`）と
   検索よけ（`x-robots-tag: noindex`）を、教材本文の入口と同じように付ける

**教材本文の入口はログインまでしか見ない**（在籍していれば読める）。
今回の入口だけが役割まで見る。2つの入口で見るものが違うことを、両方のファイルの先頭に書いた。

## なぜ「画面側の判定をサーバー側へ移す」だけでは足りないか

判定をどこへ移しても、**正解表が配信物の中にある限り取りに行ける**。
守るべきものはデータであって、画面の分岐ではない。したがって置き場を変えるのが本筋である。

## 確かめたこと（実際にその経路をたどった結果）

開発サーバーに対して、本物のログイン経路（LINE 経路の JWT）で3通り試した。

| 誰が | 応答 | 中身 |
|---|---|---|
| ログインしていない | 401 | `{"error":"Unauthorized"}`（正解表なし） |
| テスト生徒（役割 student） | 403 | `{"error":"Forbidden"}`（正解表なし） |
| テスト講師（役割 teacher） | 200 | 52,072 文字・第7講35文（`cache-control: private, no-store`） |

同じログインで画面も見た。生徒の「構文の練習」は問題が**3問**、講師は**38問**（練習3＋模範分析集35）。
本番用ビルドの配信物（`.next/static`）を機械で調べ、正解表の中身（文ID・語数・注記）が
**1件も含まれていない**ことも確かめた。

## 影響

- データベースの変更なし・費用の発生なし・外部への送信なし
- 共有事項 **C24**（模範分析集の受け渡し）に触れる。**受け渡しの向き・形式は不変**で、
  swallow-srs 側の置き場と入口だけが変わった
- 本番へ載せる荷物に含めるため `next.config.mjs` の `outputFileTracingIncludes` に
  `/api/reading/syntax-problems` を追加した（教材本文と同じ扱い）

## 見張り

`src/lib/reading/syntax-problem-access.test.ts`（9件）が、未ログイン401・生徒403・
講師200・管理者200・置き場（src と public に無いこと）・残さない指定を毎回確かめる。

## やり残し

取り込み元（quiz_generator の書き出し）は 2026-08-27 の取り込み後に中身が変わっている
（落とした情報 64件 → 68件・2文の働きが変化）。**今回は 2026-08-27 に取り込んだ内容のまま移した**。
中身の取り込み直しは別の作業として判断する（この作業は置き場と入口を変えるものだから）。
