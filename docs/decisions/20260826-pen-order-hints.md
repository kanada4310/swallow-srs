# 分析の順序の記録と検討順ヒント（筆画の時刻から・規則ベース0円）

## 背景

塾長の考え:「構文分析は最終的な解答が合っていればよいものではなく、その時点で特定できる
ものをどんどん特定して不明瞭な部分を固める——**順序も大切な作業**」。ペン入力は筆画を
時刻つきで記録しているので、(1) 生徒の分析の順序を記録し、(2) 迷ったときに
「まずこれを調べよう」という検討順のヒントを出す（追加費用0円の範囲。
指示書 2026-08-26-srs-pen-order-hints・構想は構文添削コーチ構想 v0.3〜）。

## 決定

### 1. 順序の記録は「操作の時系列 → 採点時に並びへ畳む」二段構え

- `src/lib/pen-syntax/order.ts`（純ロジック）: 記入（apply）・一手戻す（undo）・
  一覧からの削除（remove）を時系列の `OrderEvent` としてため、`reduceOrderEvents` が
  「どの記号をどの順で書いたか」の並び（`AnalysisStep[]`）へ畳む。
  同じマスへの上書きは前の記入を並びから外し、最後の記入だけ残す
- 並びの根拠は**筆画の開始時刻**（`PenPoint.t`＝入力イベント時刻）。一覧からの記入は操作時刻
- **解答データ（SyntaxAnswer）・採点データの形式は変えない**（付帯情報として別に持つ）。
  復習カード・card_states にも触れない
- 採点（＝確定）のたびに並びの控えを端末内（localStorage・直近30件）へ追記。
  **DB変更なし・外部送信なし**（サーバー保存が要るなら別起案＝塾長承認事項）
- 記録は**ペン方式のみ**（タップ方式の共有部品 SyntaxAnnotator は不変の原則を維持）。
  ペン方式内のマスタップ（一覧から選ぶ）は via='list' として記録する

### 2. 模範筆順の採取口は「講師の保存ボタン＋JSONコピー」

- 講師（teacher/admin）は採点後の「書いた順序」に「この筆順を模範の順序として保存」ボタンが
  出る。保存先はこの端末の localStorage（`ModelOrder`・保存時の読み仮名 summary つき）
- ページ下部「模範の順序（講師用）」一覧から1件ずつ／まとめて JSON コピーできる
  （「再生用をコピー」と同じ運用: 塾長が採取 → 報告に貼る → 検討順リストの並べ替え材料にする）

### 3. 検討順ヒントは規則ベース・1つだけ・答えを言わない

- `src/lib/pen-syntax/order-hints.ts`: 画面に**既に付いている記号だけ**から「確定済み」を
  読み取り（正解表は見ない）、検討順リストの「まだ確定していない最初の項目」を1つだけ提示
- 初期リスト（指示書どおり）: ①文の動詞 → ②Sの特定 → ③名詞の4役 →
  ④カッコの検討順（ルールブック「カッコの見分け方」: ［名詞］→｛ ｝→〈 〉→（ ）＝
  成立する条件の厳しい順）。**リストは設定データ（配列の並びそのもの）**で、
  塾長の模範筆順を見て後から入れ替えられる
- 文面は構想 v0.3 の3原則どおり「次に調べる対象と調べ方（辞書・文法書・ルールブックの
  引き先）」まで。正解の内容（この文の答え）は含まない（テストで機械的に担保）
- 出し方は**ボタン**「💡 迷ったらまずこれ」（実装者判断・第2層）。
  「一定時間手が止まったら自動表示」は書いている最中の割り込みが線の狙いを狂わせる
  懸念（実機不具合の教訓）から見送り、明示的な操作に寄せた。タップ方式でも使える

## やらないこと（スコープ外・指示書どおり）

- AIによる適応的な問答（構文AI試行の枠・別判断）
- 順序の自動採点・矛盾検査への組み込み（まず記録とヒントまで。実測を見て次段）
- 本編1文画面への搭載（別起案のまま）
