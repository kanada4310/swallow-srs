# 模範分析集 第7講の35文を、構文の練習に講師限定で取り込む

## 背景

塾長が模範筆順（分析をどの順で書くか）を採ろうとしたところ、
**もとになる文が3問しか登録されていない**ため採取できなかった。
第7講の35文は quiz_generator 側で確定し、問題の形への書き出しも済んでいたが、
swallow-srs にそれを読み込む仕組みが無かった。

## 決定

### 1. 取り込みは swallow-srs が取りに行く（C23 と同じ向き）

`data/sync-syntax-problems.mjs` が quiz_generator の書き出しファイルを
**読み取り専用**で読み、`src/lib/reading/syntax-instructor-data.ts` を作る。
quiz_generator には一切書き込まない。書き出し側が「受け皿の無い記号を落とした
未完成のデータを配信フォルダに置かない」判断をしているため、C22（quiz_generator が
届ける向き）ではなく C23 と同じ向きにした。

取り込み元が見つからない・数が申告と食い違う・語の並びが教材データと合わない・
まとまりの種類に受け皿が無い・講師用の目印が無い、のいずれでも**止まる**
（黙って0問にしない）。

### 2. 本文の英文は正解表に持たない（実装者判断・第2層）

同じ35文の語の並びは、すでに届いている教材データ
`public/reading-data/英語長文最前線_第7講_seg.json`（共有事項 C22）に入っており、
**35文とも語の並びが完全に一致する**ことを実測で確かめた。
そこで生成ファイルには**文ID・語数・正解表（品詞／働き／まとまり）・注記**だけを入れ、
英文は画面を開くときに教材データから文IDで読み合わせる。

- 市販教材（第三者の著作物）の本文を、同じリポジトリに二重に置かない
- 教材が届き直して語の並びが変わったら、語数の食い違いとして**分かるように失敗する**
  （黙って位置がずれた正解表を使い続けない）

### 3. 生徒には出さない

この35問は記号の一部（熟語の波線・呼応の組・まとまりに付く印・○囲みなど64件）が
落ちており、許容解も無い。したがって**講師・管理者でログインしているときだけ**
一覧に出す。生徒は従来の練習3問のまま。

- 出し分けは純関数 `syntaxProblemsFor(base, instructor, isTeacher)` に閉じ込め、
  **生徒に35問が出ないことを自動テストで固定**した
- さらに、正解表（35文ぶん・大きい）を読む側を別ファイル
  `syntax-instructor-load.ts` に分け、**講師のときだけ後から読み込む**。
  生徒の画面にはデータそのものが載らない（1ページぶん 25.6kB → 11.8kB）
- 画面には講師用の注意書きと、その文で**落とした記号**（各問の注記）を
  問題を開いた時点で出す

### 4. 働きの表記のゆれは採点でそろえる

模範分析集の転記には、深さの印（`S′`・`V″`）と2字の「同格」が残っている。
どちらも**画面で書く値と同じもの**なので、採点では同値として扱う
（深さは囲んだ括弧から自動で判定できる＝記号の台帳 2026-08-26／
例外の印は1字＝2026-08-27 塾長確定）。許容解を新たに作ったわけではない。

## やらなかったこと

- `SpanType` を増やす（落ちた記号の受け皿を作るのは別の作業）
- 許容解を作る
- 生徒に出せる状態にする
- 第7講以外の講の取り込み

## 確かめたこと（開発環境の画面・iPad Mini 相当）

- 講師でログイン → 一覧が「練習3問」＋「模範分析集 第7講（講師用 35問）」の2組・計38問
- 模範分析集の1問を開く → 講師用の注意書きと落とした記号の注記が出る
- ペンで書く → 採点する → 「書いた順序」が出る →
  「この筆順を模範の順序として保存（講師）」で保存され、
  鍵は `英語長文最前線_第7講_P6-S6`（既存3問の `ex1`〜`ex3` とぶつからない）
- 生徒でログイン → 一覧は練習3問だけ
