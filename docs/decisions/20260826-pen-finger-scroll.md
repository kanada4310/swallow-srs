# ペン入力モード中の指の扱い: 常時無効化をやめ「ペンの接近・接触中と直後だけ止める」時間窓方式に

## 決定

塾長の実機の使用感「ペン入力モード中、描画エリアでない部分を触って画面をスクロールする、
等がブロックされているのは使いづらい」を受け、画面ガードの方式を次のとおり改める
（指示書 2026-08-26-srs-pen-scroll-usability。方式選択は第2層＝実装者判断）。

1. **「ペンを一度でも見たら画面全体で指を常時無効化」をやめる。**
2. 代わりに**時間窓方式**を採る（`src/lib/pen-syntax/finger-guard.ts`・純ロジック）:
   - ペンが**接触中／ホバー中／離した直後 1.2 秒以内**（`PEN_RELEASE_MS`）に始まった
     指の接触は手のひらとみなして止める（合格条件①: 手のひらを載せたまま書ける）
   - 一度止めた接触は、窓が明けても**離れるまで止め続ける**（載せたままの手のひらが
     途中からスクロールに化けない）
   - ペンが十分離れてから始まった指の接触は普通に通す＝**描画エリア外の指スクロールが
     効く**（合格条件②）
   - ペン由来の互換タッチ（`classifyTouchContact`）は常に通す（ADR pen-input-acceptance
     の決定1を維持）
3. **線を描いている最中の画面固定（`freezeScreenDuringStroke`）は不変**（合格条件③:
   線ずれの再発防止を壊さない）
4. 「入力の記録」に、指の接触を**通した/止めたの別と理由**（ペン接触中の指＝手のひら／
   ペン接近中・直後の指／止めた接触の続き／ペンなし＝普通の指操作 等）を日本語で残す

## 根拠と捨てた方式

- **接触面積（太さ）による見分け**: 実機ブラウザが接触の大きさを報告しないことが多い
  （2026-08-25 調査済み）ため採らない（指示書の指定）
- **描画エリア内だけ指を止める方式（単独）**: キャンバスには既に touch-action:none が
  効いており、問題は**キャンバスの外**に載る手のひら。エリア内だけでは①を満たせない
- **2本指スクロールだけ常に通す方式**: 手のひらは2点以上の接触として届くことがあり、
  書いている最中に2本指例外が手のひらで誤発動すると①③が壊れる。また生徒の普段の
  スクロールは1本指が主で、②の解決にもならないため採らない
- **時間窓方式を採った理由**: 手のひらは「書く直前〜書いている間〜画と画の間」に載る。
  この間はペンが画面近くにあり、ホバー対応ペン（Apple Pencil・MPP 等）ならポインタ
  イベントで接近を検知できる。逆にスクロールしたいときはペンを画面から離しており、
  窓（1.2 秒）が明ければ普通に通せる。窓は複数画の記号の画間最長 750ms
  （GROUP_WAIT_MS）より長く取った
- **残る弱点**: ホバーを報告しない端末で、ペンが1画も触れる前に手のひらだけが先に
  着地した場合は防げない（旧方式でも初回接触前は同じ穴）。実機で問題になれば
  「入力の記録」で確認のうえ窓や判定を調整する

## 影響

- 対象は構文の練習・ペン判別の計測のみ。共有部品 SyntaxAnnotator・学習エンジン・
  データベースには触れない
- ガードは「ペンを見ていない間は何も止めない」ため常時有効化した（指だけの生徒に影響なし）
- テスト16件追加（finger-guard 純ロジック12件＋ガード/画面固定のDOM配線4件）
