# 教材の本文を、ログインした人だけが読める場所へ移す

## 背景

読解ページが使う教材データ（市販教材『英語長文最前線』の第2〜7講・共有事項 C22）は
`public/reading-data/` に置かれていた。`public` は**認証をかけずに配信するための場所**で、
そこに第三者の著作物の本文（先頭1ファイルだけで英単語およそ4,900語）が入っていた。

実際に本番へ取りに行って確かめたところ、**今のところは**ログイン無しでは取れない
（見張り（middleware）が受け持つ経路に入っていて、ログイン画面へ回される）。
ただし守りが次の1行の書き方だけに頼っていた。

```
'/((?!_next/static|_next/image|favicon.ico|.*\.(?:svg|png|jpg|jpeg|gif|webp)$).*)'
```

- ここに拡張子を1つ足すだけで、教材が誰でも取れる状態に**黙って**変わる
- `public` はもともと配信するための場所なので、置いてあること自体が食い違っている
- 検索よけ（robots）の設定も無かった

出版社との関係で問題になったときに説明がつかないため、置き場ごと変える。

## 決定

塾長が「ログインした人だけが読める場所へ移す」を選んだ（2026-08-27）。

### 1. 置き場は `private/reading-data/`

`public` の外に出す。名前をそのまま `reading-data` に保つことで、
**ファイル名と `index.json` の形（共有事項 C22）は変わらない**（変わるのは親のフォルダだけ）。
`private` という名前は「配信しない」ことがそのまま読み取れるので選んだ。

本番に載せる荷物へ確実に含めるため、`next.config.mjs` の
`experimental.outputFileTracingIncludes` で、使う4つの入口を名指しで指定する
（名前を組み立てて読むので、自動では見つけてもらえない）。

### 2. 入口は1つだけ・そこで必ずログインを確かめる

`GET /api/reading/material/<ファイル名>`。

- ログインしていなければ 401 を返し、中身は一切返さない
- **役割による出し分けはしない**（在籍していれば読める。生徒・講師を分ける必要が無い）
- 一覧（`index.json`）に載っているファイルだけを配る。置き場の外を指す名前は 404
- `cache-control: private, no-store` と `x-robots-tag: noindex` を付けて、
  端末や中継に残さない

画面側（`lessons.ts`）は取りに行く先をこの入口に変えるだけで、
読み込みの手順・エラーの扱い・見た目は変えていない。

### 3. サーバー側は自サイトへ取りに行かず、そのまま読む

構文AIの「送られてきた文が本当に教材の文か」の照合（`verifySentenceTokens`）は、
これまで**自サイトへ取りに行き、呼び出し元のクッキーを引き継いでいた**。
教材が配信されない場所へ移ったので、サーバー側からそのまま読む形にした。
クッキーの引き継ぎという壊れやすい作りが1つ減る。

### 4. 古い置き場に現れたら気づけるようにする

教材を書き出す側（quiz_generator の `deliver_reading_data.py`）は、
別の作業で直すまで**まだ `public/reading-data/` へ書く**。
そこで `scripts/legacy-reading-data.mjs` を作り、次の3か所で見るようにした。

- 開発サーバーの起動時・本番用ビルドの開始時（`next.config.mjs`）に警告を出す
- 35文の取り込み（`data/sync-syntax-problems.mjs`）を走らせたときに警告を出す
- 自動テスト（`material-access.test.ts`）が**赤くなる**

黙って見過ごさないことが目的なので、3か所とも同じ判定を使う。

### 5. 検索よけはサイト全体

`src/app/robots.ts` で全体を検索の対象から外す。
この演習室はログインした人だけが使うもので、検索に載せたいページが1つも無い。
個別に外し忘れる余地を残さないため、教材だけでなく全体を対象にした。
`robots.txt` そのものはログイン無しでも返す（見張りの通過する道に足した）。

## 検討したが採らなかった案

- **`public` に置いたまま見張りの書き方で守る**（現状）… 拡張子を1つ足しただけで
  黙って外へ出る。置き場と守りが食い違ったままになる
- **教材データをコードの中に取り込む（import する）**… 講が増えたときに
  手で足さないと届かない。C22 の「講名を焼き込まず `index.json` を読む」に反する
- **役割で出し分ける（講師だけ・受講者だけ）**… 在籍者が読めればよいという指示。
  細かくするほど、読めない生徒が出る事故のほうが起きやすい

## 影響

- 共有事項 **C22 に触れる**。置き場が `public/reading-data/` → `private/reading-data/` へ。
  **ファイル名と `index.json` の形は変えていない。**
  quiz_generator 側の書き出し先の変更は**別の作業**（この作業では触らない）
- 読解ページの見た目・手順は変えていない
- 35文の取り込み（共有事項 C24）は読み合わせ元の場所だけが変わり、
  取り込む問題は35問のまま変わらない
