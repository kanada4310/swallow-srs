# 記憶のいきもの育成（Memory Creatures）設計メモ

つばめSRS のゲーミフィケーション中核設計。Phase 10 の実装はこの文書を一次仕様とする。
（2026-06-14 ディスカッションで合意。実装はコード未着手＝計画段階）

## コンセプト

**1ノート＝1匹の生き物。** 単語帳を「無数の小さな生き物を飼う庭」として捉える。
全体の進捗で1キャラを育てるのではなく、**1枚1枚のカードがそれぞれ独立した生命**であり、
互いに関係しつつも個々に大切。デッキ＝その生き物たちの巣（ハビタット）。

### なぜSRSと噛み合うのか

**新しい学習データを一切必要としない。** すべて既存の FSRS `card_states` から導出できる。
育成ゲームは学習エンジンの上に被せる**コスメティック層**であり、スケジューラには手を入れない。

| 生き物の状態 | 元データ（既存の `card_states`） |
|---|---|
| 成長段階（卵→芽→成長期→成体→完全体） | `stability`（記憶の持続日数）をそのまま成長軸に |
| 空腹・しおれ（要世話） | `due` 超過の度合い |
| 病気・傷つきやすさ | `lapses`（忘却回数） |
| 種の個性（気難しさ等の演出） | `difficulty`（FSRS難易度） |
| 種類（植物/鉱石/動物…） | `note_type` または タグ |

生死・成長は生徒ごとの `card_states` から導出されるため、**生き物の状態は本質的に生徒ごと**
（配布デッキはノートを共有するが、card_states は個人別）。

## 成長段階マッピング（stability 基準・暫定）

| 段階 | 条件（暫定） | 見た目 |
|---|---|---|
| 卵 | state = new | たまご（未孵化） |
| 孵化／芽生え | state = learning | ひな／芽 |
| 成長期 | stability < 21日 | 若い芽〜苗 |
| 成体 | 21日 ≤ stability < 60日 | 成長した姿 |
| 完全体 | stability ≥ 60日 | 完成形・誇りの対象 |

- しきい値は実データを見て調整する（FSRS の retention 設定にも依存）。
- `lapses` が多い個体は、同じ stability でも「弱っている／傷がある」見た目に寄せる。

## 世話＝復習（状態オーバーレイ）

`due` 超過に応じて、成長段階の上に「世話が必要」の状態を重ねる：

| 状態 | 条件（暫定） | 演出 |
|---|---|---|
| 健やか | due 未到来 | 通常 |
| おなかすいた | due 超過（軽度） | 空腹アイコン |
| しおれ気味 | due を `interval` の数倍超過 | しおれた見た目 |
| 危篤 | さらに長期放置 | 弱り切った見た目 |
| 死（墓石） | 致命的に長期放置 | 墓石に変化 |

学習画面では復習を「エサやり／水やり」として演出し、正答で成長アニメを出す。

## 死＆復活メカニズム（重要・SRSとの両立）

学習科学を壊さないため、以下を厳守する：

- **「死」は見た目の層に限定する。** スケジューラや card_states を破壊しない。
- **「ゼロから育て直し」は FSRS が自然に実現する。** 長期放置カードを久々に復習すると
  ほぼ Again になり、FSRS が `stability` を大きく下げる → 生き物が卵／芽に戻る。
  「サボった結果わからなくなって、また一から」が科学的に正しいまま成立する。
- **死は必ず復活可能にする（安全弁）。** 墓石をタップ → 復習（=お墓参り）で生き返る。
  永久ロストにはしない。罰ではなく「もう一度会いに行こう」の温度感。
  小中学生が「墓場だらけ」で心折れないための UX 配慮。
- **検討された代替（採用しない）**: 死亡時に該当カードを強制的に新規リセットする Option B。
  SRS の蓄積を捨てるトレードオフがあるため、まずは上記の自然リセット方式を採る。
  後日「もっと強い喪失感」が必要になった場合の選択肢として記録のみ。

## 個別の見た目（手続き生成＋インプリント）

「全部別の絵」を現実的なコストで実現するため2層構成：

1. **手続き生成スプライト（自動でユニーク）**
   - 単語ID／見出し語をシードに、色・形・模様・アクセサリを決定論的に合成。
   - 6858匹すべてが別の見た目になる。手描きアート不要・カードあたりコストゼロ。
   - 実装候補: シードハッシュ → SVG パーツ合成。

2. **初回インプリント（生徒の入力）= キーワード法／視覚化記憶術**
   - そのノートに初めて触れた時、生徒が絵文字／写真／候補からその子の「顔」を刻む。
   - 単語に自分のイメージを結びつけると定着する（記憶術として機能）のが本質的な価値。
   - **生徒ごとの個別データ。** 配布デッキ共有でも生徒Aと生徒Bの同じノートは別の姿。

### 必要なデータモデル追加（唯一の新規）

生徒×ノートのコスメ用テーブル（小規模）を1つ追加する：

```
user_creature_state (
  user_id    UUID,
  note_id    UUID,
  imprint    JSONB,   -- 刻んだ絵文字/画像参照/選択バリアント
  nickname   TEXT,    -- 任意のニックネーム
  ...
  PRIMARY KEY (user_id, note_id)
)
```

- card_states（生死・成長の導出元）はそのまま。これは「見た目の刻印」だけを持つ。
- オフライン（Dexie）対応必須。

## ランキング・集計レイヤー（公平性配慮）

- ストリーク、デイリーミッション（今日◯匹の世話）。
- クラスランキングは**絶対量ではなく成長率**で競う（学習が遅い子に配慮）。
- プライバシー: オプトアウト可能に。
- バッジ: 「初めての完全体」「100匹の庭」「お墓参りで復活」等。

## アートディレクション（決定: 2026-06-14）

**癒しの動物／小さな生き物系。** 植物系は形状が似がちで差分が作りにくいため不採用。
体形＋耳/角＋しっぽ＋色＋模様など**パーツの組み替え**で、手続き生成と無限の差分を両立。

**タッチ（重要）**: 自然で素朴・落ち着いた手描き風イラスト。単線（細め）＋ミュートな
アースカラー（くすんだ緑/クレイ/スレートブルー/オーカー/トープ）。**高校生も使うため、
幼すぎる表現は避ける**——大きな潤んだ目・きらきらハイライト・キャンディカラー・
ピンクほっぺは不採用。ネイチャージャーナル／野鳥図鑑のような、ほっとする質感を狙う。
怖さやとがりはなし。小動物（鳥・きつね・かえる・はりねずみ・ふくろう・かたつむり等）を
シンプルに描き分ける方向。

- **パーツ案**: 体形（丸/ぷに/もこもこ）・目（数・形・表情）・耳/角/触角・口・
  ほっぺ・体色・模様・アクセサリ。各パーツを単語IDシードで決定論的に選択。
- **成長段階の見た目**: 卵 → ぷにっとした幼体 → 子ども → 成体 → 完全体
  （大きく・パーツが増え・アクセサリが付く）。`stability` 段階に対応。
- **弱り/しおれ**: 同じ個体が「しょんぼり目・色あせ」に。墓石は共通グラフィック。

## 実装順（合意）

1. **育成ゲーム（Phase 10）を先に。** 既存 FSRS データだけで作れるため即効性が高い。
2. その後に **リッチコンテンツ表示（数式・画像、Phase 13.x）** で数学・理科へ科目拡張し、
   そこの生き物も飼えるようにする。
