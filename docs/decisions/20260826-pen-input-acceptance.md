# ペン入力の受け付け方針: ペン由来の互換タッチは止めない・描画中は画面を固定する

## 決定

塾長の実機（タブレット＋ペン）で発生した致命的不具合2件
（①正しい部分でもペンが反応しなくなる ②線を引くと常にずれる）への対策として、
ペン入力の受け付け方針を次のとおり定める。

1. **ペン由来の互換タッチは止めない。** 多くのタブレットでは、ペンの接触そのものが
   互換タッチイベントも発生させる。手のひら対策の画面ガード（ペンを見たら画面全体で
   指を無効化）が全タッチを一律に preventDefault すると、**ペンのタップがクリックに
   ならなくなり、ボタン・候補チップが反応しなくなる**。タッチが「ペン由来」
   （touchType が 'stylus'、または直近のペン接触と時間 500ms・距離 32px 以内）なら通す
   （`classifyTouchContact`・純ロジック）
2. **線を描いている間は画面全体の移動を止める。** 描画中に画面が動くと、狙った位置と
   線の位置がずれる。ポインタを受理してから離すまで、文書全体で touchmove / wheel を
   preventDefault する（`freezeScreenDuringStroke`）。あわせて、ペン初回接触で出る
   「手のひらOK」バッジは**場所を常に確保**し、出現によるレイアウトずれを無くす
3. **ピンチズーム中はブラウザ計算の要素相対座標（offsetX/Y）を使う。** 一部ブラウザ
   （特にアプリ内ブラウザ）では、表示域が拡大・移動している間、イベントの画面座標と
   要素位置の座標系が食い違い、線が常に一定量ずれうる。表示域が変形しているときだけ
   offsetX/Y に切り替える（`resolveLocalPoint`。通常時・テスト環境は従来の
   「画面座標 − 枠の位置」のまま）
4. **診断を最優先で備える。** 「入力の記録」（受理/拒否した接触の種類・座標・理由と、
   描画中の画面移動の検出を時系列でコピーできる）を計測ページに常設、構文の練習に
   折りたたみで設置。実機でしか再現しない問題は、この記録を貼ってもらって確定させる

## 根拠

- 症状1はコード上で機序を特定できた（ガードの一律 preventDefault → クリック抑止 →
  候補チップが閉じられない → キャンバスも線を無視 → 全く反応しないように見える）
- 症状2は複数原因がありうる（バッジ出現のレイアウトずれ・描画中のスクロール・
  ズーム中の座標系食い違い）。特定できた分は塞ぎ、残りは診断記録で確定させる
- いずれも実機でしか再現しないため、開発環境の擬似入力だけで「直った」と判定しない
  （指示書 2026-08-26-srs-pen-input-critical-fixes の方針）

## 実装方針

- 純ロジック（テスト可能）: `classifyTouchContact`（palm.ts）・`resolveLocalPoint`
  （local-point.ts）・`input-log.ts`（記録の作成・整形・画面移動の検出）。テスト14件
- 画面ガード `usePenScreenGuard` は文書全体でペンのポインタ位置を追跡し、
  タッチ到来時にペン由来かを判定。判定結果は記録コールバックへ流す
- 保険として、候補チップ・一覧モーダルのボタンはペンのポインタイベントでも発火する
  （クリックが死んでいる環境でも先へ進める。二重発火は時刻で抑止）
- 「ペンのみ」既定・手のひら拒否の枠組み（ADR pen-pos-letters の⑥）は維持

## 影響

- 対象は構文の練習・ペン判別の計測・お手本登録のみ。共有部品 SyntaxAnnotator・
  学習エンジン・データベースには触れない
- 記録は端末内で完結し、外部送信しない
