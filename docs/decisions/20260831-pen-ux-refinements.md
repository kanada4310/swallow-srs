# 書き味と画面の改修5件（○囲みの選択式化・自動確定・働きの付け替え・行またぎ下線・入れ子カッコの縦ずらし）

## 背景

塾長の実機の使い込みで、構文の練習（ペン入力）の書き味の不満が5件挙がった
（指示書 2026-08-31-srs-pen-ux・仕様は塾長と往復して確定済み）。
着手前の調査で、例外の印（仮・真・強・同）の**入力経路による扱いの割れ**も
見つかったため、先にそれを一本化してから5件を実装した。

## 決定

### 0. 例外の印の採点データを一本化する（下ごしらえ）

従来は、ペンで○囲みを書くと4字とも採点対象外の `extras` に入り、
タッチで「同」を選ぶと `answer.role` に入って**採点される**という二重構造だった。
入力経路によらず同じデータ・同じ採点になるよう、印ごとに入れ物を1つに決めた:

- **仮・真・強 → `extras`（採点対象外）**。理由は2つ。
  ①正解表に定義が無い（模範分析集 第7講の取り込みでも4字とも「落とした印」として
  正解表から落ちている）ため、採点しようがない。
  ②強は「is = V ＋ ○強」のように**働きの値と同じ単語に共存する**ため、
  1マス1値の `answer.role` に入れると働きを消してしまう。
- **同 → `answer.role`（働きの値・採点される）**。
  正解表に働き「同格」の定義が**実在**し（第7講）、採点の同値化（`roleBase`）で
  「同」≡「同格」になっている。同は下線の塊の働きとして単独で書かれるので
  他の働きとマスを取り合わない。

採点との整合はテストで固定した: 仮・強の印を付けても採点は1点も変わらない／
正解表に定義の無い単語へ「同」を書いても減点されない（採点対象外のマス）／
正解表に「同格」がある単語では「同」が正解になる。

### 1. ○囲みの手書き認識は廃止し、タッチ選択式にする（確定仕様1）

判別の入口（`recognizeGroup`）から○囲み漢字の検出を外した
（`classifyExceptionMark` は削除せず、入口だけ閉じた）。付け外しは:

- **仮・真**: すでに判定済みの **S / O のマスをタッチ**すると出る一覧の
  「例外の印」から付ける・外す。働きが S / O でない単語では押せず、
  働きを S / O 以外に変えると印も一緒に外れる。仮と真は同じ単語に同時に付かない
- **強**: 働きのマスの一覧から付け外し（どの働きとも共存できる）
- **同**: 働きの一覧の「同」を選ぶ（従来どおり・採点対象）

○囲みを手書きすると、台帳外の形（circle）として「タッチで付ける」案内が出る。
お手本の任意登録・計測ページのお題からも○囲み漢字を外した。

### 2. 候補が未確定のまま次の字を書いたら、最有力候補で自動確定する（確定仕様3）

従来は書き始めた瞬間に候補を破棄しており、テンポよく書くと**前の字の判定が
黙って失われた**。書き始めで候補を取り置き、線の行方で後始末を分ける:

- **続けて書いた** → 最有力候補で自動確定（誤りは判定欄のタッチで直せる）。
  自動確定した事実は「入力の記録」に残す
- **枠の外の軽いタップ** → 従来どおり閉じるだけ（✕と同じ破棄）

決定記録 `20260827-pen-chip-interrupt` のうち「閉じた候補は取り消しと同じ扱い」
だけをこの決定で置き換える。**受付を止めない・候補を押す操作と書き始めを
当たり判定で分ける・記録に残す**は維持。計測ページも同じ扱いにし、
自動確定は救済（候補）として数える（お題は据え置き＝書きかけの線は
同じお題の書き直しとして判定される）。

### 3. 働きの記号は、下線の塊のどの単語の下に書いても塊の最後の単語に付く（確定仕様2）

吸着した単語が既存の下線の塊（ul の範囲）の中なら、塊の最後の単語
（末尾の句読点は除く）に付け替える。塊が複数重なるときは最後の単語が
いちばん後ろのもの。既存の解答データを見るだけで判定でき、新しいデータ構造は無い。
タッチでマスを直接選んだときは付け替えない（狙ったマスに入れる意思が明確なため）。

### 4. 行をまたぐ下線は、3条件がそろったときだけ連結する（確定仕様4）

「前の行の末尾まで下線が達している」かつ「その下線にまだ働きが書かれていない」
かつ「次の行の行頭から下線が始まっている」の3条件（塾長確定）がそろったときだけ、
新しく書いた下線を前の行の下線とひとつながりの塊にする（span の to を伸ばす）。
**行末・行頭の許容誤差は語単位（句読点のみ無視）**とした。ペンの横位置のぶれは
吸着（35%重なり）が先に吸収しているため、画素単位のしきい値を持ち込むより
判定が安定する（実入力で狭すぎると分かれば、端の語1つぶんの緩和を検討する）。
連結は書いた順（前の行→次の行）のみ。判定に全行分の単語箱が要るため、
`applySymbol` に追加情報（単語の文字列・全行の単語箱）を渡せる引数を足した。
描画（`underlineSegments`）は元々複数行対応なので変更なし。

### 5. 入れ子カッコは縦にもずらして、線の重なりを解消する（確定仕様5）

同じすき間に並ぶ括弧を、横6px（従来）に加えて**縦8pxずつずらして斜めに離す**
（`BRACKET_SLOT_H`）。縦の並びは開き・閉じとも**外側のまとまりほど上**＝
同じまとまりの開きと閉じが同じ高さにそろう向き。深さ別の4色の色分け
（2026-08-28）は不変。表示だけの変更で、吸着・採点・保存データに触れない。

## 根拠・確かめたこと

- テスト827件全緑（着手時807・新規20件）。うち自動確定の配線テストは
  修正前のコードでは失敗する形（前の字が破棄され pos が入らない）
- 開発サーバーの実ブラウザで、印の付け外し・自動確定・付け替え・連結・
  縦ずらしを目視確認（詳細はハンドオフ 2026-08-31-pen-ux）

## 影響しないもの

共有部品 `SyntaxAnnotator`（タップ方式）・読解1文画面（構文を分析する）の語彙
（`ROLE_OPTIONS`）・採点ロジック（`syntax.ts` は無変更）・認識エンジン
（shapes/geometry/templates/pdollar）・DB・費用・外部送信。
変更はすべてペン入力2画面（構文の練習・ペン判別の計測）専用の部品に収まる。
