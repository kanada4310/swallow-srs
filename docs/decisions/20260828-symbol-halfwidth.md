# 記号の見た目の幅をそろえる（丸括弧・山括弧を半角へ）

## 背景

記号の台帳（`src/lib/pen-syntax/ledger.ts`）で、**丸括弧 `（ ）` と山括弧 `〈 〉` だけが全角**、
角括弧 `[ ]` と波括弧 `{ }` が半角で、並べたときに幅が食い違っていた。
塾長の提案（2026-08-27）により、山括弧の半角は数学用の **`⟨ ⟩`（U+27E8 / U+27E9）** を使う。

## 決定

1. 台帳の表示名を半角にそろえる（`( )` `⟨ ⟩` `[ ]` `{ }`）。
   初回お手本登録の説明文も同じ字にそろえた
2. **画面に描く字も同じ字にそろえる**（`src/lib/reading/syntax.ts` の `SPAN_TYPES` の
   `open` / `close`）。文の上に実際に描かれる括弧はこちらから来ており、
   台帳だけ直すと**同じ画面の中で候補と描かれる括弧が食い違う**ため
3. **説明の文（`label` / `short`）とAIへ渡す文面は全角のまま**にする。
   これらはルールブックの書き方に合わせた説明であり、
   構文AIの判定・問答の文面と揃っている必要があるため（下記「タップ方式の扱い」）

## 過去に保存した記録が読めなくならないことの裏取り

記号の見分けに使っているのは**記号の ID**（`paren-open` など）と
**まとまりの種類の名前**（`adv` など）で、**見た目の字は表示にしか使っていない**。
自分で確かめた範囲:

- 台帳の表示名は `symbolLabel()` からしか読まれず、読み先はすべて画面の文字列
  （候補の名前・お手本登録の案内・分析の順序の表示・計測ページのお題）
- 模範の順序（講師用・端末内）と入力の記録は `AnalysisStep.symbol` に **ID** を持つ。
  照合の鍵 `orderKeyFor()` も ID から作る
- 書き込みの保存（`reading_progress`）と採点はまとまりの**種類の名前**で行う。
  AIへ渡す文面 `serialize.ts` は `label`（今回変えていない）を使う

見た目の字が使われる保存物は、構文分析カードの表示用HTMLだけ。
これは保存時に組み上げた文字列なので、**過去のカードはそのまま読める**
（新しく作るカードから半角になる）。

テスト `src/lib/pen-syntax/ledger.test.ts`（2件）で、
括弧8種の表示が半角であること・照合の鍵が字ではなく ID から作られることを固定した。

## タップ方式の扱い（実装者判断・第2層）

指示書の「タップ方式の丸括弧もそろえるか」については、
**画面に描く字（`open` / `close`）だけそろえ、説明の文（`label` / `short`）は全角のまま**とした。

- 描く字をそろえないと、ペン方式の候補と実際に描かれる括弧が食い違う（上記2）
- 説明の文は構文AIの判定・問答へ渡る文面で使われ、
  ルールブックとシステム側の文面（`prompt.ts`）が全角で書かれている。
  ここだけ半角にすると、AIに見せる書き方が2通りになる。
  構文AIの試行は現在停止中だが、**再開したときに揃っていない状態を残したくない**
- タップ方式は読解の1文画面と共有の部品だが、変えたのは描く字だけで、
  **保存する書き込み・採点・AIへ渡す文面は不変**

## 影響

データベースの変更なし・費用なし・外部への送信なし。
共有部品 `SyntaxAnnotator` に触れているため、**本番反映の個別承認を省略する例外
（`20260827-scoped-push-exception`）の範囲（ペン入力の2画面）には当たらない**。
