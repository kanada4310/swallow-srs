# 引き継ぎ 2026-08-27 — 続けて書いた記号が1つにまとまる問題の解消

指示書: `統合塾運営エージェント/docs/work-orders/2026-08-27-srs-pen-commit-latency.md`
ADR: `docs/decisions/20260827-pen-commit-latency.md`
設計の1枚（更新）: `docs/pen-input-architecture.md`

## 3行まとめ

- 塾長の実機フィードバック「書き込んでから読み取られるまでの間、すべてが1つの記号として
  認識されてしまう」を、**触れた瞬間に境界（行・段・単語）をまたいでいれば待たずに確定**する
  ようにして解消した。同じ単語の同じ段で書き続けている間は従来どおり待つ
- まとめ判定を `grouping.ts` に集約し、場所の比較相手を「まとまり全体の外接箱」から
  **直前の1画**へ変更。書き込み部品と計測ページの複製も `useStrokeGrouping` に一本化
- 速さの計測を新設（実機用の記録欄＋合成データの計測）。テスト 730件全緑（開始時 711件）

## やったこと

### 1. まとめ判定の作り直し（`src/lib/pen-syntax/grouping.ts` 新設）

`snap.ts` の `shouldGroupStrokes` を移し、判定を作り直した。切る根拠を上から順に:
間があいた（0.9秒）→ 行がちがう → 段がちがう → 横長の線（下線・波線は1画で完結）→
単語をまたいだ → 単語がちがう → 記号として大きすぎる → 直前の画から離れている。

「直前の画のすぐそば（12px以内）」なら単語・距離は見ない（複数画の文字を切らない）。
ただし本文の帯に重なる記号（括弧）は、近くても付き先の単語がちがえば切る
（`…）` と `［…` が語間で隣り合う場合）。

### 2. 境界で即確定（`src/components/pen-syntax/useStrokeGrouping.ts` 新設）

ペンが触れた瞬間（`onStrokeStart`）に境界をまたいでいれば、その場で確定する。
1点しか分からないので確信のある根拠だけで切る（括弧は本文の上端より上から
書き始めるため、段の判定に余裕を取り、際どい位置は切らずに書き終えてから判定し直す）。

待ち時間 0.75 秒は据え置き。効くのは「書く手を止めたとき」だけになった。
短縮は画数の多い記号（○で囲んだ漢字は6〜10画）を切る危険があるため見送り。

### 3. 複製の解消

書き込み部品（`PenSyntaxAnnotator`）と計測ページ（`pen-lab`）に複製されていた
まとめ判定・タイマー・確定処理を `useStrokeGrouping` へ一本化。
`useStrokeCanvas` の `onStrokeStart` が書き始めの点を渡すようにした。

### 4. 速さの計測（今回が初めて）

- 実機: 確定のたびに「入力の記録」へ `確定 N画 …（理由） 最後の一画から=◯ms
  次を書き始めてから=◯ms` を残す。計測ページに「確定までの時間（速さの計測）」欄
- 合成データ: `simulateCommits` で新旧を比較（旧判定は `legacyShouldGroupStrokes` として残置）
- 再生テスト: `replayGrouping` を追加し、症状の記録を `replays/2026-08-27-fast-writing-merge.json`
  に収録（**症状を再現できる形に書き起こしたもの。実機からコピーした生の記録ではない**）

## 計測の結果

**合成データ（画面の寸法と書く速さを模した計算。実機のペンで測った値ではない）**

| 見るもの | 新方式 | 旧方式 |
|---|---|---|
| まとまりの一致率（n=60回） | 100.0% | 58.1% |
| 次を書き始めてから前が確定するまで（11記号を続けて書く） | 平均 0ms | 平均 140ms |
| 書き終えてからその記号が形になるまで | 平均 268ms | 平均 494ms |
| 11記号を書いたときに確定したまとまりの数 | 11 | 8 |

**開発サーバーの実ブラウザ**（Playwright・iPad Mini 相当・テスト生徒アカウント・
マウスで書く設定）: 隣の単語に書き始めた瞬間に前の記号が確定。記録は
`確定 1画 次の記号に入った瞬間(単語がちがう) 最後の一画から=183ms 次を書き始めてから=1ms`。
JSエラーなし。2画面（構文の練習／ペン判別の計測）とも表示を確認。

**判別の精度は測り直していない**。今回の変更は「どの画を1つの記号にまとめるか」だけで、
判別器そのものには触れていないため（既存の判別の計測は全件そのまま通っている）。

## 既知の限界

- 同じ単語の同じ段に、続けて別の記号を書くと1つのまとまりになる
  （人にも区別できないため。書き直し＝同じ記号として扱う従来どおりの挙動）
- 書き終えた直後に「採点する」を押すと、最後の記号が待ち時間に間に合わないことがある
  （従来どおり・今回の変更で悪化はしていない）
- 判別に迷った記号の候補チップが、書いている最中に出るようになった
  （従来は次の画を書き終えてから。チップが出ている間に新しい線を受け付けないのは従来どおり）
