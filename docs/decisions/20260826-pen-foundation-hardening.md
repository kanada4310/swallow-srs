# ペン入力の基盤の作り込み（ゾーン方式・入力/座標の一元化・記号台帳の確定版・記録の再生）

## 背景

ペン入力はこの2日で機能追加と実機不具合の修正（下線ずれ→ペン無反応・線ずれ→
指スクロール→お手本義務化）を細かく重ね、入力・座標・記号・認識の各層に
場当たりの継ぎ足しがたまっていた。数えた設計の弱点は6点:
①入力処理が4か所に重複 ②採寸のやり直し条件が列挙式（漏れると下線ずれが再発する構造）
③画面ガードが時間窓方式（ペンを離して1〜2秒のラグ） ④記号の一覧が分散
⑤入力の記録が読み物どまり（テストにできない） ⑥設計の全体を書いた文書が無い。
次の機能（分析の順序の記録・1文画面への搭載・生徒展開）を安心して積むため、
塾長承認のもと基盤を一度作り込む（指示書 2026-08-26-srs-pen-foundation-hardening）。

## 決定

### 1. 画面ガードをゾーン方式へ変更（塾長裁定・時間窓方式を廃止）

- **書き込みエリアの中**（`data-pen-write-zone`）: ペン専用（指・手のひらは無効）
- **エリアの外**: ペンは無効（書く道具に徹する・ボタンは指で押す）。
  **指は常時有効**＝ペンを離した直後でも待ちなしでスクロールできる
  （塾長の指摘「ペンを離して1〜2秒はラグがありすぎる」への対応）
- 候補チップ・一覧・お手本登録の枠は「ペン用の操作部品」（`data-pen-ui`）として
  ペンでも指でも押せる（第2層判断。書く流れがペンだけで完結する）
- 手のひらは2段で防ぐ: 描画中の画面固定（従来維持）＋**ペン接触中に始まった指は
  区域を問わず止め、離れるまで止め続ける**（載せたまま書ける・途中でスクロールに化けない）
- ペン由来の互換タッチは常に通す（8/26 修正の維持）。純ロジック `zone-guard.ts`＋
  配線 `usePenZoneGuard.ts`。旧 `finger-guard.ts`（時間窓）と `usePenScreenGuard.ts` は削除

### 2. 入力と座標の一元化（弱点①②の解消）

- 入力イベント処理（受理判定→捕捉→画面固定→座標変換→線の組み立て→入力の記録）を
  `useStrokeCanvas` に集約。書き込み部品・計測ページ・お手本キャンバス・計測ページの
  登録欄の**4か所の重複を解消**（登録欄は共通部品 EnrollCanvas へ置き換え）
- 単語の箱の採寸を `useTokenBoxes` に集約し、**やり直し条件の列挙をやめて
  毎描画後に測り直す**（変わっていなければ更新しない）。ResizeObserver＋フォント
  読み込みも拾う。「表示が変われば採寸が自動で追随する」を仕組みで保証

### 3. 記号の台帳・確定版を適用（塾長指示・第7講の実物で裏取り）

正本は新設の `ledger.ts`。使う記号をこれに限定する。
- 品詞（上の段）: n・v・a・ad・aux（**p を廃止**＝前置詞は働きの段の P。練習の正解表も更新）
- 働き（下の段）: S・V・O・C・P・Po・▷・**＋（等位接続詞・単語囲み○の置き換え）**・同格
- **深さ（S′ ″ ‴）は書かない**: 囲んだ括弧から自動判定し、入れ子括弧と同じ色＋
  控えめな自動ダッシュ印で表示。印刷・照合では `dash-notation.ts` がダッシュ表記へ
  相互変換（第7講データとの採点同値）
- **○で囲んだ漢字の例外マーク**（仮・真・強調・同格）を判別対象に:
  円＋中の字画の組を検出し、本人のお手本と照合（無ければ候補チップから選ぶ）
- **[ ] と { } は開始カッコの真下にまとまり全体の働きを書ける**（`StudentSpan.role`・
  第7講 P8-S3 の実例。矛盾検査の「[ ] に役割なし」も充足扱い）
- 波線＝熟語（慣用表現）の印として維持
- 台帳外（?・ダッシュ・Ø・斜線・単語囲みの○・M）: 検出はするが**反映せず書き方を案内**
  （誤って別記号に化けるより親切）。お手本登録・計測のお題からも外した（必須21→20種）

### 4. 入力の記録を再生テストに（弱点⑤）

「入力の記録」に**再生用 JSON のコピー**を追加し、`replay.ts` が記録を判定ロジックに
通し直せるようにした（ガード判定・座標変換・描画中の画面移動）。これまでの実機不具合
3件（ペン無反応・線ずれ・指スクロール不能）を `replays/` に収録し再生テスト化。
今後の実機不具合は「記録を貼れば再現テストになる」。

### 5. 設計の1枚

`docs/pen-input-architecture.md`（層と責務・座標の約束・機種差の吸収点・台帳の在りか）。
今後のペン入力改修セッションはこれを最初に読む。

## 影響・互換

- 見た目・操作感の変更はゾーン方式と台帳適用に伴うもののみ（エリア外のボタンは指で
  押す旨の案内・働き凡例に＋・深さの色と印・空マスの記号を「＋」→「・」に変更
  〔＋が実記号になったため〕・群Bのお題の入れ替え）
- 読解1文画面（構文を分析する）の語彙（S/V/O/C/M/前O/接）・書き込みデータ・構文AIは不変
- 登録済みのお手本・完了印はそのまま有効（p など台帳外の登録は無害な残置）
- DB変更なし。テスト 688件全緑（開始時664件）

## 見送り・残り

- 例外マークの候補チップは上位3件表示のため、お手本未登録だと4種目（同格）が
  チップから選べない（登録すれば上位に来る。実測を見て並び方を調整）
- タップ方式（共有部品 SyntaxAnnotator）には深さの色分け・カッコ下の働き欄は未搭載
  （ペン方式のみ。共有部品は読解1文画面と共用のため別起案）
- 「順序の記録・検討順ヒント」「1文画面への搭載」は次の指示書（スコープ外）
