# ハンドオフ 2026-08-26（第2便）: ペン入力の致命的不具合2件の修正＋診断の仕組み

指示書: 統合塾運営エージェント `docs/work-orders/2026-08-26-srs-pen-input-critical-fixes.md`
ADR: `docs/decisions/20260826-pen-input-acceptance.md`

## 塾長の報告（実機・タブレット＋ペン）

1. 正しい部分でもペン先が反応しなくなることがある
2. ペンで入力すると画面がずれて、線を引くと常に線がずれる（致命的）

## 原因と直し方

### 症状1: ペンが反応しなくなる（コード上で機序を特定）

- **原因**: 手のひら対策の画面ガード（ペンを一度見たら画面全体で指のタッチを無効化）が、
  **ペン自身の接触に付随して発生する互換タッチイベントまで一律に止めていた**。
  多くのタブレットではペンの接触もタッチイベントを伴い、それを preventDefault すると
  ペンのタップがクリックにならない＝ボタン・候補チップが反応しなくなる。
  さらに候補チップが開いている間はキャンバスが線を無視する設計のため、
  チップを閉じられなくなると「ペンが完全に反応しない」ように見える
- **修正**: タッチが「ペン由来」（touchType='stylus'、または直近のペン接触と
  時間500ms・距離32px以内）なら止めない（`classifyTouchContact`・`usePenScreenGuard`）。
  保険として候補チップ・一覧モーダルのボタンはペンのポインタイベントでも発火する
  （クリックが死んでいる環境でも先へ進める。二重発火は時刻で抑止）

### 症状2: 画面がずれて線がずれる（原因候補3つを塞いだ・実機で要確認）

- **候補a（特定）**: ペン初回接触で「🖐手のひらOK」バッジが出現し、書いている最中に
  画面レイアウトが下へずれる → **場所を常に確保**し表示だけ切り替える（回帰テストあり）
- **候補b**: 描画中にページがスクロールして狙いがずれる → **線を描いている間は
  画面全体の touchmove / wheel を止める**（`freezeScreenDuringStroke`）
- **候補c**: ピンチズーム中の一部ブラウザ（アプリ内ブラウザ等）でイベント座標と
  要素位置の座標系が食い違う → **表示域が変形している間だけブラウザ計算の
  要素相対座標（offsetX/Y）に切り替える**（`resolveLocalPoint`）
- 合格条件「線を引いている最中に画面が動いても、線は英文に対して正しい位置に置かれる」は
  b（動きを止める）＋毎イベントの枠の測り直し（従来からある）＋c で担保する設計

### 診断の仕組み（指示書の最優先事項）

- **「入力の記録」**: 受理/拒否した接触の種類・座標・理由、ブラウザ計算座標との差、
  描画中の画面移動（枠位置・スクロール・表示域・倍率の変化を「⚠ 画面移動」行で明示）を
  時系列で記録し、**ワンタップでコピー**できる。端末内で完結（外部送信なし）
- 置き場所: ペン判別の計測ページに常設＋構文の練習ページの下部（折りたたみ）
- 構文の練習には「無効化した接触 N件」の表示も追加（誤って捨てた場合に気づける・指示書2）

## 塾長への実機再確認の案内（完了報告にも記載）

1. 本番の「構文の練習」でペンで書く（括弧・下線・文字・ボタンタップ）
   - 前回「反応しなくなった」操作を一通り試す
2. 「線がずれる」が再現するかを見る（ズームした状態・していない状態の両方で）
3. **症状が出たら**: ページ下部「入力の記録（ペンの不具合の報告用)」を開く→
   「記録をコピー」→そのまま秘書への報告に貼り付ける（計測ページなら常設の同パネル）
4. 記録に「⚠ 画面移動」行があるか、ペンの接触が「拒否」されていないかで原因が確定できる
